# 表格的分与合：分解（2026-09-27，用户确认，Q89–Q92 按建议）

**目标**：让输出里的每张表对应原件上的一张表——该接上的续表接上，一个外框里的几张表拆开，混进表格的表题移出，不是表格的东西不当表格——内容不丢，结构对了读者和下游程序才能正确理解。程序能通用解决的先在程序里解决（没有待办的文档也受益），程序判断不了的由 Agent 用 Q87 的工具修正。

**费用**：程序部分全部离线（冻结 run 的响应缓存回放），不产生服务费用；Agent 验证用 Codex（包月，Q88 费用约定）。

## 2. 范围

**做**：

- 合：跨页续表的对齐条件；
- 原生表格的合并单元格；
- 分：一个外框里的几张表；
- 边界：混进表格的表题；少一行的三处先查清成因；
- 图片里读出的"表"不是表；
- 标注修订；
- Agent 验证。

**不做**：

- 截图里的界面表格保留与否：属于输出约定，评审第 7 节，单独议题（Q92）；
- 单元格里的字符错误。

## 3. 工作项

| 项 | 内容 | 改动 | 测试与验收 |
|---|---|---|---|
| T1 合 | 续表对齐：扫描引擎读出的表只比左边（右边随内容变化）；原生表格仍比两边 | `tables/merge.py` | 单元测试：左齐右不齐的扫描表接上，左边不齐的不接；ocr01 接成 2 张 |
| T2 原生合并单元格 | 从 PyMuPDF 的单元格矩形恢复 colspan / rowspan：一个格子覆盖几条列线就跨几列，行同理；被覆盖的位置不再是空格子 | `content/pdf_native.py` 的 `_grid` | 单元测试：画一张有合并单元格的 PDF 表；全语料统计有合并单元格的原生表有多少、输出怎样变（有跨格的表渲染为 HTML，与扫描页一致），逐篇核对 |
| T3 分 | 一个外框里的几张表：在通栏行（一个格子跨全部列）处拆开，条件是通栏行上下两段用到的列划分不同；通栏行成为段落，放在它下面那张表之前（是不是标题由标题步骤与 Agent 判断）；拆开后的表各自去掉全空的行和列 | 新的通用步骤（`tables/`），在流水线里接在表格读出之后、续表之前 | 单元测试：两段列结构不同的拆开，相同的（分组行）不拆；unseen_pdf_tables01 第 4–6 页拆开；unseen_scan_form01 等不变 |
| T4 边界 | 表格的第一行或最后一行其实是一行跨列的文字（一句话被列线切开，各格拼起来是连续的句子）时移出表格，成为段落；少一行的三处先查成因再定 | `content/pdf_native.py` 或 T3 的步骤 | 单元测试；paper_chn02 的 Tab.6 移出 |
| T5 图中的假表 | 扫描引擎在工程图、流程图里读出的表：先查引擎给出的信号（图片路由类别、描述的类型、单元格内容），有通用条件就在程序里改为文字；没有就留给 Agent（figure Skill 说明） | `content/scan.py` 或 Skill | patent01、unseen_word_spec01 的假表消失，或 Skill 里写明 |
| T6 标注修订 | text_pic02 的两张页面表；paper_chn02 的期刊页眉表；paper01 的图表数据表（Q90）；unseen_pdf_tables01 若拆分结果与标注在细节上不同，以页面为准 | `ground_truth/`，记入 `docs/annotation_changes.md` | 每处附页面依据 |
| T7 Agent 验证 | 程序修不好的地方，Agent 能否用 `unjoin`、区域重读替换改对：用 Codex 在 T1–T5 之前的状态上跑受影响的文档（或造例），看它是否发现并改对、花多少 | 无代码改动，或 Skill 的说明 | 至少一处真实文档上 Agent 用新工具改对，或说明为什么不需要 |

## 4. 顺序

T1 → T2 → T3 → T4 → T5 → T6 → T7 → 全语料回放对比、重新冻结。T2 在 T3 之前：原生页的通栏行要靠合并单元格才能认出。每项完成后跑 L0、L1，提交一次。

## 5. 退出条件

- **表格结构**：
  - ocr01 的表格数与标注一致；
  - unseen_pdf_tables01 第 4–6 页拆开，列与页面一致；
  - paper_chn02 的表题不在表格里；
  - 假表消失或已交给 Agent。
- **不退步**：全语料 char_f1 逐篇不低于冻结值（容差 0.005）；表格 F1 不下降，下降的逐篇核对并说明（标注有误的按 T6 修订）。
- **有意的变化**：输出变化的文档逐篇核对并记录，冻结 run 重新冻结。
- **规则**：每处改动是通用条件并有单元测试，不按文档写规则。
- **测试**：L0、L1 通过。
