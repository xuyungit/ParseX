## 5. A-codex：直接从原件开始的通用 Agent

### A0：实验边界

| 允许 | 不纳入本臂 |
|---|---|
| Codex 自身主模型的看图、推理、终端和文件能力 | ParserX 解析流水线及四个解析工具 |
| PyMuPDF/Poppler、PDF 原生文本与图像提取 | PaddleOCR、RapidOCR、Tesseract、商业 OCR 等识别服务或引擎 |
| OOXML、python-docx、LibreOffice 转换与渲染 | 额外视觉问答或转写服务模型 |
| 模型自主编写辅助脚本、裁图、拼接和检查 | 其他臂的 Markdown、来源候选和修复建议 |
| 同一主模型反复查看局部原件 | 标准答案、得分反馈、联网检索同一文档的现成文本 |

这里的“不额外配置工具”指不开发专用解析接口或配备识别模型。基础软件负责打开、提取、渲染和保存；Agent 自主组织处理。不得把“纯 Agent”曲解为禁止原生文字复制、禁止写脚本或只能一次读完整篇。

首轮使用一个 Codex 主 Agent，不预设子 Agent 编排。保留动态脚本和工具日志，脚本计入方法产物与维护成本。允许生成脚本，但不允许开发者在盲测期间替它针对文档打补丁。

### A1：最小技能包

开发位置预定为 `experiments/agent_only/skill/`，不安装到全局、不改变其他会话。第一版以指令为主：

1. 输入、输出、忠实转写及不总结、不补写事实的约定。
2. 先盘点文档与页数，再自行选择原生读取或视觉转写。
3. 看图可放大和裁剪；原图与裁剪映射保存；无清晰证据时停止猜测。
4. 原文、图像保留与模型图示说明分开；复杂表格允许 HTML，公式使用 LaTeX。
5. 把逐页完成状态、跨页关系、理解和未解决项落盘，支持长文继续处理。
6. 交稿前核查全文覆盖、数字符号、表格、图片引用、标题和跨页接缝。

不要求 A 实现 ParserX 的完整 IR 或行号分配协议；交付一致，内部自由。若技能正文演变为大量文档例外，停止扩写并归纳成通用方法。

### A2：探针和完整文档

- 与 U1 同期开发，在相同困难页观察能否识别主要障碍；完整比较使用完整文档。
- 开发阶段先覆盖原生文字 PDF、公式论文、扫描表格、Word 各类；长文档另作压力测试，不把短页结论外推到数百页。
- 运行时只给任务、原件和技能包，不预先提供对这份文档的错误诊断。
- 主模型与 U 的主 Agent 尽量一致，记录差异；产品级比较允许各臂有其固有服务依赖，不能把总体差异归因于单一因素。
- 初步可行后冻结 Skill 和宿主环境，在新会话做两次独立在线运行；严禁复用上一次答案作为输入。

### A3：宿主与评测

宿主只负责启动、超时、收集文件和日志，不偷偷执行 OCR 或 ParserX 生成初稿。通用预处理有实际调用时记下版本、命令和输出。

每次至少交付：`document.md`、`assets/`、页或区域对应记录、未解决项、Agent 与 shell 轨迹、动态脚本、用量与耗时记录。记录文件名与确切结构在 A1 后冻结；缺少观测能力时明确标为未知，不能编造看图次数或费用。

结果由运行会话之外的评测器统一计分。现有 `scripts/agent_explore.py` 固定从 ParserX 初稿出发，不能直接改名当作 A；可复用宿主的记录和审计代码，但需独立启动路径。

## 6. 共同实验安排

1. **准备轮**：冻结起点，整理数据来源，修正评测盲点，定共同输出和报告字段；新增盲测清单作为独立准备项。
2. **开发轮**：U1 与 A1/A2 独立推进，各自可调提示；每次变化有版本。不等待对方完成才开始我们的两条线。
3. **候选轮**：U2/U3 与 A3 完成，冻结候选和 Skill；先在既有回归集比较，准备新盲测。
4. **验收轮**：共同清单、冻结评测器、同一原件。主要候选各运行两次；若发生完成状态差异或严重错误不一致，整份文档补第三次，全部报告。
5. **互审轮**：收集 U-other 冻结产物，先按原件复核输出，再比较实现、权限约束和维护量。
6. **融合轮**：每项吸收写清来源、解决的问题、引入代价和验证；形成新候选，重新回归并用新的留出数据检验。

“没有严重错误”仅限定已逐项核查的样本范围。少量样本和两次重复用于发现不稳定，不足以证明所有文档都可靠。未执行或失败计入完成率，标注修订后全部臂统一重算。

## 7. 冻结运行包与交叉检查

各臂包内至少包括：

- commit、patch、依赖锁定和运行命令；Skill/prompt/config 的版本及哈希。
- 输入清单、覆盖范围、标注和评测器哈希；正式运行的隔离方式及已知不足。
- 全部 Markdown、引用资产、来源对应、未解决项、原始轨迹和错误输出。
- 每文档每次指标、人工原件核对记录、预算中止与人工介入。
- 费用的实付/标价估算/未知区分；冷启动、缓存和总时长。
- 已知失败、哪些问题还需继续研究、不能支持的结论。

互审以“文档—页/区域—现象”为单位，不以总分排序替代。收到对方结果后不覆盖我们的冻结包；新增观察和采纳修改另记。

最终选择可为改进流水线、Agent 技能包，或有清晰切换条件的组合。保留哪部分由复测决定；不默认把双方全部模块叠加到最终产品。
