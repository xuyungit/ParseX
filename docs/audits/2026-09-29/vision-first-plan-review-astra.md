## 1. 本轮分工

双方从同一个计划文件和同一代码基线独立推进；共同基线文件保持原文，本文作为审查补充，不把建议默认为对方已经接受。

| 工作线 | 负责人 | 范围 |
|---|---|---|
| U-other | 对方开发方 | 按共同计划升级现有 ParserX，完成 P0、V 和适用的 C1 实验，提交实现、输出和报告 |
| U-codex | 我们这边 | 在独立 worktree 中，基于同一计划独立改进现有 ParserX |
| A-codex | 我们这边 | 原件交给通用 Codex，通过技能包和通用工具自主转换，不用 ParserX 解析工具、OCR 服务或额外视觉服务模型 |

对方不承担 A-codex 的实现、适配或运行。本文提及它仅用于说明最终比较关系，不能因此扩大对方本轮工作范围。

双方先共享输入、输出约定和评测口径，各自完成首轮实现与运行后冻结结果，再互换实现进行审查。互相吸收后的版本另起实验轮次，保留吸收前的结果。

## 2. 总体审核结论

**有条件支持进入小规模实验。先修正完整性保证和实验口径，再按探针结果决定是否铺开。**

支持以下方向：

1. 暂停为个别错误追加内容规则；保留 `content-by-region` 作对照，不直接合并。
2. 用页面视觉理解产生结构和转写候选，尽可能从原生文字复制。
3. 保留工作区、表格结构、DOCX 读取、来源记录、修改历史和四工具接口。
4. 程序负责引用、账目、格式、资源预算和记录；Agent 根据证据作内容判断。
5. 先 P0，再扩展；保留自由转写与全页送入的对照。

不支持在实验前宣布新设计能保证不漏、不编造，也不建议为了维持已有工程投入而预先限定最终架构。最终取舍应看完整交付物的质量、稳定性、时间、维护量与可追溯性。

## 3. 必须修订的六项

### R1：完整分配只保证输入归属，不能保证语义完整

对应计划 §3.3、§6.5。“每行恰好分配一次”应保留，但删除“因此整块遗漏必然可见”“人工只需看 write 块”的保证。

反例：

- `write` 声明替换十行，正文只保留九行；账目仍完整。
- 正文被错误分配为 `aside`；有理由不代表排除正确。
- 图片、矢量图或公式根本不在文字行集合中；完整分配对此没有约束。
- `copy` 行号合法，但引用位置、阅读顺序或表格归属错误。
- 图内文字归入图片，最终裁图却切掉部分内容。

建议：P0 对整页检查，覆盖 copy、write、aside、表格、图、脚注及顺序。把“输入分配合法率”“原件内容覆盖率”“转写正确率”分开报告。被程序补回的行单列为修复，不能提升模型首次分配合法率。

契约还必须允许无文字行锚点的内容，以页码、坐标区域、图片或引擎条目为来源。原生行与视觉发现内容分别登记，不能为了恰好一次而丢弃后者。正文被写入 aside 或并入图时，必须留下可核对的最终去处。

### R2：原始排版数据与推断标签分开

对应计划 §3.2、§3.7。坐标、字号、字体、基线和 PDF 字符映射是提取数据；“这是下标”“这是阅读顺序”仍是推断。

输入可提供行内 span 的原文、框、字号、字体、基线、映射异常，以及单独的上下标候选。保留原始字符；不要把推断后的 Unicode 上下标写成唯一可复制原文。这样模型才能纠正推断，也能回查 44 处假下标一类问题。

普通页的上下标不能仅凭“已有排版事实兜底”就认定已覆盖。保留 V-all 和未分流普通页的检查，报告实际漏检类型。图片旋转和坐标转换复用现有约定，不另起隐含坐标系。

### R3：Agent 可凭图改原生数字，审计不等于验证

对应计划 §3.1、§3.5、§10。支持 Agent 根据清晰原件采用与文字层不同的数字，不把 OCR 一致作为唯一许可条件。

每次内容修改保留原值、新值、来源区域、所用证据、理由和版本。看不清时保留 unresolved；不为了交稿强行确定。改动必须经过独立评测判定，关闭待办、写出理由或两个模型一致都不能记为修复正确。

当前实现尚有硬门：`parserx/tools/edit.py` 的 `_correct` 经 `correct_gate` 接受修改，区域 `_adopt_region` 检查原生数字和字符召回。四工具表面可不变，但实现、Skill、指导文档与测试必须同步，否则计划中的能力并未真正开放。放宽内容判定不应放宽引用存在、来源定位、范围合法、历史留存等检查。

### R4：既有隔离集重新定性，增加真正未参与开发的文档

对应计划 §1.1、§6、§7。`patent01` 和 `paper01` 已出现在规则来源、细节分析和验收项中。

证据见 `eval_reports/2026-09-29_content_by_region.md` §3：#15、#16、#21、#25、#27、#31，以及 §4 的具体目标。它们可继续作为回归集；本轮不再称作严格盲测。`text_pic02` 是否未暴露也需检查，不凭目录名判断。

双方共同补充新盲测文档，开发期间不可查看标准答案和逐项得分。清单、输入哈希和标注哈希在最终评测前冻结。新盲测未准备好不阻止开发探针，但届时不能给出泛化验收通过的结论。

### R5：补关键信息盲点，先冻结评测再比较

本次直接调用 `compute_key_content_errors`，以下三对内容的 total 都是 0：

| 原件与输出差异 | 涉及含义 |
|---|---|
| `数值为 10` / `数值为 -10` | 正负号 |
| `$x^2$` / `$x_2$` | 指数与下标 |
| `甲为 10，乙为 20` / `乙为 10，甲为 20` | 数值所属对象 |

这不表示整个指标组都无法发现这些问题，但现有关键内容总数不能单独作为真实性验收。除未经 NFKC 的差异，还须检查符号、单位、上下标、对象或单元格归属、公式结构及遗漏。以通用的反例类别验证检查器，不把这三个字符串写成特殊规则。

人工核对对象是原件，既有 expected.md 也可有错。修订标注要留证据和版本，并对所有实验臂统一重新计分；不能只给当前方案改分。评测器修订后，所有冻结输出使用同版重算。

### R6：修订基线表及成本口径

计划 §1.2 的数字与当前本机 `eval_runs/bench/report.md` 已不一致。该报告标记时间为 2026-09-29T11:32:22，15 篇组的关键内容错误：fixed 512、hybrid 565、Datalab 535。因此该快照不支持“hybrid 的关键内容错误领先所有工具”。这也不等于宣布 Datalab 总体更优。

`parserx/tool_eval/runner.py` 的汇总逻辑对时间、费用、关键错误求和，对其他指标求均值。报告里的 LlamaParse `$0.88` 是该组记录费用之和，不能直接标为每篇费用。主 Agent 的标价估算、实际服务账单与缓存回放必须分别列出。缺失费用记为未知，不能把未知或订阅折算为免费。

先固定 run、代码、标注、指标、输入哈希，重新生成同口径表，再据此讨论质量和成本。历史缓存输出可重新计分；回放用时不能与在线工具耗时直接比较。

## 4. 对其余设计问题的意见

| 问题 | 审核建议 |
|---|---|
| 行内公式导致整行重写 | 可作 P0 的简单起点，统计误改范围；若失败集中在此，再引入 copy/write 片段，不预先设计字符级复杂协议 |
| 参数配置还是提供方适配层 | 支持同一接口下用参数配置；验证实际响应。接口形状、图片或 reasoning 传递不同才需要适配，不按品牌建层 |
| JSON 结构化输出 | 同时量首次合法、重试后合法、机械修复和最终失败；截断、空回复、超时单列。格式合法不等于内容合法 |
| 推理强度 | 按每个模型实测支持的值写运行矩阵；计划 §5 写 GLM 不支持 medium，§6.1 不能不加区分地统一 low/medium |
| 表格与标题 | 保留现有能力。模型提议范围、角色仍需核对；表格网格正确不能弥补行分配错误；逐页理解后需全文标题与跨页检查 |
| 工作区衔接 | 复用 Block、Observation、Evidence、Decision 和现有账目；补稳定 source IDs、分配映射和无文字层内容来源。P0 先独立存实验 JSON，通过后再决定最小数据模型变更 |
| 不可识别字符和 LaTeX | 不通过删除字符或猜写来“满足格式”。无法恢复时保留原图、未解决状态及可见标记；原始证据保留原码点 |
| 服务模型选择 | 以探针选择；强模型结果只作参照，不称理论上限。质量可行性与价格筛选分开 |

## 5. 共同验收协议草案 C0

以下是提交双方核对的共同口径。原计划不因此被静默改写；接受的差异记录在各自运行 manifest，口径有分歧时单列结果，不混成一个排名。

1. **输出一致**：忠实 Markdown、被引用的图片等资产、页或区域到输出的轻量对应记录、未解决项、执行记录。复杂表格允许 HTML；公式用 LaTeX；图示说明明确区分原文和描述。交付要求相同，不强制三臂内部 IR 相同。
2. **输入一致**：相同原件字节；PDF、DOCX、扫描件按类型分组。U 臂本轮升级范围仍为原生 PDF，其余格式作回归；A 臂的扩展结果另列，避免比较范围错位。
3. **开发与验收分开**：开发页可反复调试；新盲测使用冻结实现、Skill、模型设置和评测器。每个主要候选做两次独立在线运行；差异大时按预先规则补第三次，全部保留，不挑最好一次。
4. **质量先于成本排名**：逐文档、逐页报告关键错误、遗漏、表格和公式关系、标题与顺序、资产完整、未解决项和完成率。抽查范围内的严重错误须逐项解释，格式改善不能抵消它们。未检查部分不声明零错误。
5. **失败进入分母**：超时、解析失败、预算用尽、未执行、人工接管全部展示；不能只在共同成功子集上得出总体优胜结论。
6. **成本分层**：服务、主 Agent、冷启动、缓存、重试、总时长、人工时间分别记录；缺测记未知。原计划 $0.005/分流页保留为经济性目标，质量通过但超预算记为“质量可行、经济性未达标”。
7. **先冻结再互审**：提交代码或补丁、精确模型配置、输入输出哈希、原始轨迹、全部结果、失败清单及已知限制。审查时先对原件判错，再看实现原因。
8. **吸收后重新验证**：列出每项借鉴及来源，形成新版本；在回归和新的留出样本上验证，不能拼各版本最优分数宣称最终版。

## 6. 给对方的实施次序和交付清单

1. 记录 R1–R6 的处理意见，冻结本轮基线和共同口径的接受版本。
2. 做 P0：原计划难页加干净对照，整页人工核对，输出原始与修复后合法率、具体误改和漏项、时间费用。
3. 根据 P0 决定继续、缩小范围或暂停某条设计；某模型失败不自动否定方法。
4. 做 V、V-a、V-all，并完成完整文档的结构与跨页检查；解释路由漏项和表格、标题回归。
5. 按原计划做 C1，报告实际改对、改错、漏看和未解决项，不以待办清零评价效果。
6. 提交可复核的冻结运行包和代码差异，供双方交叉检查。若新增盲测尚未完成，报告结论为开发验证，不提前宣称最终版本验收。

本轮目标是用可核对的证据确定保留和替换哪些能力。对方可独立选择实现方法；新增局部条件应说明适用范围、通用依据、失败案例和整体影响。
