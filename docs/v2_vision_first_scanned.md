# 扫描页走视觉：方案草稿（2026-09-30，本方计划第 1 项）

> 原生页的做法见 [执行计划](v2_vision_first_execution.md) 与 V、C1 报告；这里只写扫描页的不同之处。
> 2026-09-30：用户同意先做探针；探针结果见 §7。

## 1. 现状与差距

- **现在怎么处理扫描页：**
  - 扫描引擎（PaddleOCR-VL-1.6）整页识别，识别出的每一块成为工作区里的一个块，并记一条账目（`ocr_block`）；
  - 页眉页脚按引擎的标签排除；
  - V 不送扫描页，交给 Agent 前的初稿就是引擎的识别结果。
- **差距：**
  - ocr01（9 页扫描报告）：补丁版 7；V 初稿加 Agent 后 9–10，多出的主要是合并格与标注重复写法的差异；Datalab 4。
  - 其他扫描件（ocr_scan_jtg3362、unseen_scan_form01、8 篇 omnidoc 扫描单页）的情况，看本轮 C1 铺开的结果。

## 2. 做法：对着引擎的块做完整分配

分工与原生页相同：服务模型看图写，程序记账、比对，Agent 定夺。区别在于可照抄的不是文字层的行，而是引擎读出的块。

**给服务模型的材料：**
- 页面图；
- 引擎的块，逐块编号（K1、K2……），每块给出框、类型，以及文字、表格 HTML 或公式 LaTeX；
- 本地识读（RapidOCR）的行，作为另一份独立读数；
- 版面检测区域。

**服务模型回答：**
- 按阅读顺序排列的块序列，每块由几部分组成：
  - `copy`：照抄某个引擎块；
  - `write`：照图重写，写明它替换哪几个引擎块；
  - `table`：用引擎的表格，有问题的格子用 `cell` 按位置改；
  - 图上有、引擎没读到的内容：不对应任何引擎块，给出页面区域。
- `aside`：页眉页脚等不进正文的块。页眉页脚按方案 B 写进页标记。

**不变量：** 每个引擎块恰好出现一次。这对应原生页的"每行一次"，保证引擎读到的东西不会悄悄丢掉。

**程序比对与保守默认值：**
- 重写的文字，与被替换的引擎块、与本地读数分别比较字母和数字。
- 重写里新出现的数字，两份独立读数都不支持时：保留引擎的文字，重写作为候选列进待办，交给 Agent。

**公式和表格：** 沿用 v5、v6 的做法，公式另请一次，表格按格改。

## 3. 哪些扫描页送

- **按页、按信号送，与原生页一致。** 信号就是流水线已有的待办：读不出的字、本地读数看得到而输出里没有的文字、输出里有而页面上看不到的文字、表格算术不一致等。没有信号的页照用引擎结果。
- **另外全送一次作对照。** 扫描件的错误多是静默的，要量一下按信号送会漏掉什么。

## 4. 与 Q144（Chandra）的关系

- 引擎读数的来源可以替换：先用现有的 PaddleOCR-VL 做。
- Chandra 专项如果证明它更好，可以作为引擎本身，或者作为第二份读数。

## 5. 验证

2. **整篇：**
   - 文档：ocr01、ocr_scan_jtg3362、unseen_scan_form01、8 篇 omnidoc 扫描单页；
   - 对比组：补丁版、Datalab、本轮 C1。
3. **回归集：** patent01 的扫描页留到最后。

## 6. 待定

- 扫描件的错误多是静默的，按信号送是否足够，还是要更积极地送？
- 本地识读的质量能不能作为独立读数，尤其是手写、低清晰度的页？

## 7. 探针结果（2026-09-30，报告 `eval_reports/2026-09-30_scanned_probe.md`）

- **分配可行：** 8 个难页、luna-medium 与 deepseek-medium 各两次，32 次里 31 次一次合法、1 次重试后合法。
- **收益集中在引擎出大错的页：** 一页被漏读整段的英文论文，从 157 降到 60–77，与 Agent 相当；其余 7 页基本持平。
- **§2 的保守默认值（新数字两份读数都不支持就保留引擎文字）不能用：** 不受支持的新数字 20 个里 17 个是对的，按整块回退会退掉被漏读的整段。改为只挂信号、不回退。
- **按信号送：** 引擎空块、本地识读有而引擎没有的文字、引擎读数远少于框内本地识读。
- **行间公式：** 探针里照抄或照图写，没有另请一次。
- **写回工作区：** 未做，这是接进 V 的下一步。
