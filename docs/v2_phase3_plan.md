## 0. 目标与退出条件

**目标**：用未见过的文档回答 Q13——默认运行时是固定流水线、Agent（Codex），还是"默认固定流水线、难例交 Agent"。工具包与 Skill 冻结，比较的是运行时，不是工具。

**退出条件**：

1. **运行完成**：未见集每篇文档、每个运行时各 2 次有效运行（§2.3），卫生审计与完整性检查通过；无效运行作废重跑。
2. **对比报告**写入 `eval_reports/<日期>_p3_runtime_comparison.md`，内容包括：
   - 逐篇、逐运行时的质量；
   - 两次运行之间的波动；
   - 主 Agent 与工具内服务各自的费用与耗时；
   - 人工介入；
   - 混合方案按预先确定的分流规则（§2.5）算出的结果；
   - Q13 的建议。
3. **用户对 Q13 作出决定**，写入指导 §14；指导 §12、§15 与 §0 的下一阶段启动清单更新。

## 2. 实验设计

### 2.1 运行时

- **固定流水线 v2**：`workspace init → process → export`，与 Agent 的第一个工具相同的标准处理，没有后续判断。
- **Codex**：`codex exec --json`，主 Agent gpt-6-sol、推理强度 medium，每次在命令行上显式指定；默认经 `ask_image` 看图；隔离设置与阶段二相同。
- 服务层模型不变（Q40）：gpt-6-luna、PaddleOCR-VL-1.6。

### 2.2 快照与规则

- 用户确认本计划时的提交做一个工具快照，两种运行时共用；整个阶段不改工具、Skill、任务说明。
- 规则 r2（不允许为文档写转换逻辑，只读脚本可用）；截止时间按 Q39（100 页以下 30 分钟）；运行中不提示 Agent。
- 发现缺陷：记录，不在本阶段修。若某个缺陷使某篇文档在所有运行中都无法完成，停下来交用户决定。

### 2.3 运行次数与缓存

- 每篇文档、每个运行时各 2 次，每次使用空的响应缓存（全部真实请求），用来看同一输入的波动。
- 固定流水线的第一次运行另外冻结为 `eval_runs/<日期>_p3_fixed_v2`，供以后回放。
- 合计 24 次运行：固定流水线 12 次（几分钟）、Codex 12 次（同时最多 3 个会话）。

### 2.4 计数与评分

与阶段二的运行记录相同：

- **主 Agent**：token、步数、耗时、按标价折算的费用；
- **工具内服务**：请求数、费用、耗时；
- **质量**，按用户的优先级（信息保全与使用体验 > 标题层级 > 其他指标）排列：
  - 信息类：char_f1、表格 F1、关键内容错误、漏表与多表；
  - 标题：heading_f1，另列标题角色 F1（Q46）；
  - 待核对项数（文档摘要的 `review`）；
- **人工介入**单独记账；
- **汇总**：取每篇两次运行的平均与差值。

### 2.5 混合方案（预先确定分流规则）

混合方案不另外运行，由已有结果算出：固定流水线处理后，按规则决定哪些文档交给 Agent；交出去的取 Agent 的结果与费用（Agent 的第一步本来就是同一个标准处理），其余取固定流水线的结果。

**分流规则在运行前定下，不看未见集结果再改**（建议见 Q52）：

- 固定流水线导出的文档摘要中 `review.open > 0`（有待识别页、失败块、没有层级的标题、可能的续表、表格算术或可疑字符提示）；
- 或文档状态不是 `complete`。

报告另外给出描述性分析：各类待核对项与"Agent 是否带来改进"的对应关系。这部分只作参考，不用来改规则。

## 5. 各项分解

### P3-1 开跑前准备

- **实验装置**：
  - 按文档清单找输入与标注，能读 `ground_truth_unseen/`（加 `--gt-dir`，或按 `configs/phase3_unseen.txt` 查找）；
  - `summary` 按清单排序；
  - 装置本身的改动照常先写测试。
- **开跑前检查**：服务检查三项 OK；L0；两个 L1；两个冻结 run 的回放。
- **快照**：生成阶段三快照（记录提交号、Codex 版本、配置指纹）。
- **冒烟检查**：在验证集 `val_word_template01` 上用快照跑一次 Codex，确认装置与快照端到端可用。不在未见集上做任何试跑。

### P3-2 固定流水线 ×2

- 每篇两次，每次空缓存；第一次冻结，并用 `--replay` 验证。
- 核对：去向平衡、sidecar 合法、文档摘要中的 `review`。

### P3-3 Codex ×2

- 每篇两个独立会话、两个独立实验目录，每个目录的缓存都从空开始；同时最多 3 个会话。
- 每次运行后做卫生审计与完整性检查；无效运行作废重跑，重跑原因写入记录。

### P3-4 评分与分析

- **评分**：用评测器给全部 24 次运行打分，再算标题角色 F1 与待核对项数。
- **两组分开汇总**：新文档 3 篇、隔离集 3 篇。
- **混合方案**：按 §2.5 的规则算出混合方案的质量与费用。
- **逐篇查看 Agent 的改动**：修改、结构调整、排除，判断哪些是改进、哪些是退步；发现的缺陷记入清单，留给阶段四。

### P3-5 报告与 Q13

- 写对比报告（§0 第 2 条），给出 Q13 的建议与依据，交用户决定。

### P3-6 收尾

- 更新指导：§12（阶段三状态）、§14（Q13）、§15、§0.2（阶段四启动清单）。
- 未见集的去向按 Q54 处理。
