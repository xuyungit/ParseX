# Agent 的角色与自己的循环（Q87、Q88，2026-09-27）

来源：外部评审 [architecture-review-astra.md](audits/2026-09-27/architecture-review-astra.md) 与用户讨论（2026-09-27）。用户同意写入指南并开始开发。

## 1. Q87 Agent 的角色：从校对员到能重新解释局部的编辑

**现状**：Agent 是校对员，只在初稿的框架里改。

- 块怎么分、哪些是表格，初稿已经定了。它能改文字、单元格、角色、顺序、续接，能采用整页或图片的识别结果。
- 表格被识成普通文字、两张表被误当续表、标题和正文没有换行可拆，这些它修不了。
- 评审的说法："工具已经摆脱运行时，Agent 还没有摆脱初稿。"

**不做**：

- 不把批量识别、图片描述交给 Agent 调度。阶段二已经测过，那样慢而且贵（P2-4）。
- 不让 Agent 自由重写正文。内容仍然只来自原件的读数，每处修改都有证据。

**四项**：

1. **文档理解记录**
   - `edit_draft` 加操作 `note {text, scope, evidence?, replaces?}`：结论、适用范围（如"第 20–35 页"）、证据编号。
   - `replaces` 指向被修订的旧记录。记录只能修订，不能删除，历史保留。
   - `read_draft` 加视图 `notes`，摘要里列出条数。
   - 记录随 sidecar 输出，因为 sidecar 就是整个状态。上下文清理之后，循环把全部记录放回上下文（§2 第 3 条）。
   - 记录是可修订的解释，与原件事实分开。Agent 不需要读文件的能力：工作区里的东西都经四个工具读写。
2. **凭证据的例外**：规则分三类。

   | 类别 | 例子 | 处理 |
   |---|---|---|
   | 正确性约束 | 引用存在、顺序无环、内容有来源、不静默丢内容、续表的列数一致（网格合法） | 程序硬检查，不能突破 |
   | 文档经验 | 同一部分里同一编号模式同级；续表在相邻页、中间只有页眉页脚 | 默认检查；凭证据可以突破 |
   | 输出约定 | 标题不跳级（Markdown 的层级连续）；界面文字不输出 | 统一执行 |

   - 突破的方式：结构操作带 `override: true`，同时必须有 `evidence` 和 `reason`。
   - Decision 记下突破了哪条经验、凭什么证据。
3. **局部重新解释**
   - **读**：`view_source {page, bbox, as: text}` 让识别引擎重读页面上的一个区域，得到文字、表格、标题。
   - **换**：`edit_draft adopt {page, bbox, evidence}` 用这次读数替换区域里的块。程序检查三件事：
     - 内容守恒：旧块的文字在新读数里找得到，找不到的作为待办留下；
     - 原生文字层的数字不因识别而改变；
     - 旧块保留，状态为 duplicate，与整页采用相同。
   - **撤回**：`unadopt {evidence}` 恢复采用之前的块。
   - **拆开合并的表**：`unjoin` 也能拆开合并的表格。合并时记下接缝在哪一行，拆开时两张表各自恢复。
   - 原生页上，结构取自读数，文字尽量取原生文字层（按位置对齐）。具体规则在实施时按代码确定，写回本节。
4. **没有待办的文档**
   - 先在全语料上测量"没有待办、但标题或结构有错"的文档有多少。
   - 再决定要不要用便宜模型（gpt-6-luna，每篇约 $0.01）只看大纲做分诊，可疑的再交给强模型。

## 2. Q88 自己的循环：上下文与模型

**实测**（s5：循环 + gpt-6-sol，5 篇）：

- 固定前缀（任务说明、Skill、工具定义）1.2 万 token；约 11 轮后上下文 2.6–9.3 万 token。
- 新读入的 token 总量约等于最后一轮的上下文：每个 token 只按原价付一次，之后都命中缓存（十分之一的价格）。
- 所以费用主要来自新读了多少，不是历史有多长。

**设计**：

1. **中立的对话记录，每家一个适配器**
   - 对话以统一格式保存：任务、文字、工具调用、工具结果（文字与图片）、各家的推理内容。推理内容是不透明的数据，只原样回传给同一家。
   - 适配器负责请求格式、缓存标记、推理内容、工具结果里的图片、schema 转换。
   - 先做两个：
     - `responses`：OpenAI Responses API；
     - `chat`：OpenAI 兼容的 Chat Completions，DashScope、DeepSeek 等用它。工具结果不能带图时，图片作为紧随其后的一条用户消息。
   - Anthropic 原生接口以后需要时再加。
2. **上下文的构造**：固定前缀（任务说明 + 工具定义）加只追加的历史。改写历史会让改写点之后的缓存失效，所以不逐轮压缩。
3. **清理**
   - 上下文超过阈值（默认 10 万 token）时，一次性把较早的工具结果换成一行占位，注明是哪次调用、需要时重新读取；最近 4 个结果保留。
   - 模型自己的调用和文字保留。
   - 随后追加一条消息：上下文已清理，附理解记录全文和已做修改的条数（`read_draft` 的 `changes` 视图可看）。
   - 不让模型写摘要：状态都在工作区里。
4. **图片**：同一个工具 `view_source`，两种看法。
   - `vision: agent`：`as: image` 的图片放进工具结果，Agent 自己看。工具结果里的图片超过上限（默认 6 张）也触发清理。
   - `vision: tool`：不放图片，Agent 用 `as: answer` 请视觉模型回答（Q47 的默认）。
   - 哪个做默认，测量后再定（§3）。
5. **收尾与预算**
   - 到截止时间的 80%，或 Agent 费用达到预算（`budget_usd`，默认不设），追加一条"现在交稿并写报告"的消息。
   - 到截止时间，或费用达到预算的 1.2 倍，才强行停止。
6. **配置 `runtime.agent`**：
   - `engine`（codex / loop）、`model`、`effort`；
   - `api`（responses / chat）、`endpoint`、`api_key`：不填时用服务层 VLM 的端点与密钥；
   - `vision`（tool / agent）、`budget_usd`、`clear_at_tokens`。
7. **模型的要求**
   - 必需：可靠的函数调用（参数是 JSON Schema）、足够的上下文、中文。
   - 可选：看图（用于 `vision: agent`）。纯文本模型经 `as: answer` 也能完成任务。

## 3. 验证

- **看图方式**：循环 + gpt-6-sol，`vision: agent` 与 `vision: tool` 在扫描页、表格多的几篇上对比质量、费用、用时。
- **换模型**：循环 + qwen3.6-plus（DashScope，`chat` 适配器）跑 s5 的同样 5 篇。
- **长文档**：real_doc03（87 页）用循环跑，看清理是否触发，以及费用与质量。
- **局部重新解释**：用两个场景验证（表格被识成文字、两张表被误合并），检查内容守恒与撤回。
- 工具看过程指标，质量分数只防退步；每种配置只跑一次时，只下"能用、没有退步"的结论。

## 4. 顺序

Q88 → 理解记录 → 凭证据的例外 → 局部重新解释 → 分诊的测量。每一项完成后跑 L0、L1，提交一次。
