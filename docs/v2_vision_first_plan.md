## 0. 摘要

- **系统**：ParserX 把 PDF、DOCX（含扫描件与图片）转成给大模型用的 Markdown，附 sidecar（块、来源、去向账目）。架构是工作区 + 程序约束 + 四个 Agent 工具 + 混合运行时：固定流水线先做，有待办再交 Agent。指导文档是 [redesign_guide.md](redesign_guide.md)。
- **位置**：对标 15 篇，表格、标题、字符、关键内容错误都领先 LlamaParse、MinerU、Datalab、PaddleOCR-VL（§1.2）。落后在只有看页面图像才看得见的东西：公式、上下标、字体画出的字形、画出来的图。
- **最近两轮**：先为公式打了 5 个补丁；再按计划 [v2_content_plan.md](v2_content_plan.md) 整体重做（分支 `content-by-region`，10 个提交）。有真实改进，也有退步；逐条去掉实测的规则盘点表明，多数新条件是看到一处错误后补的几何阈值，互相牵制，其中一条是错的却被另一条依赖（§1.3、§1.4）。
- **判断**：让程序用几何阈值猜含义这条路走不通，继续整理规则也还在同一个框子里。起作用的都是把"看"交给页面读数的部分。
- **提议**：按人整理文档的方式分工。模型看页面图、写出这一页，文字层作为"可复制的原文"一并交给它；程序只做事实抽取、机械核对、记账渲染；拿不准的交 Agent 看图（§3）。
- **先实验再重建**：7 篇文档、两种输入、两次重复，与补丁版和规则版对比；Agent 自己看图对比委托视觉模型一起做。判定标准事先写定（§5）。实验结论出来前不加规则、不合并分支（§6）。

## 1. 背景与数据

### 1.1 系统里与本题有关的部分

- **原生 PDF**：文字层（PyMuPDF）是正文字符的来源；本地版面检测器（pp_doc_layoutv3，CPU，免费）给区域；本地识别（RapidOCR，免费）对每页读一遍，作为"页面上看得到什么"的独立证据；扫描引擎（PaddleOCR-VL，服务）整页读，给出带 LaTeX 的读数，目前只用于含公式的文档。

## 2. 诊断

1. **程序在猜含义。** "这是下标吗、是标题吗、这两段要接上吗、哪份读数更好"是含义判断。指导 Q56 与 2026-09-23 的规则分类早已写明：这类判断只能作证据交给模型，程序只执行正确性约束。实施时在对标分数的压力下一次次破例，每条规则只在见过的那篇文档上成立。
2. **规则互相依赖，局部修正变成全局牵制。** 撤一条错的要连带改另一条；加一条挡错的同时挡掉对的。
3. **评测看不见一部分退步。** 规范化把上下标折叠；逐篇看图靠人眼，量一大就漏。
4. **上一版计划的方向对，落地又回到了规则里。** "结构来自页面图像、字符来自文字层"是对的；但"结构来自页面"落成了程序里的区域几何与比例常数。另一会话写的简化方案（`content-by-region` 分支上的 `docs/v2_content_simplification.md`：统一页面几何模型、按同字体常用字号判上下标）仍在规则的框子里，只是整理得更整齐，**撤回，不实施**。
5. **不是问题的部分**：工作区、去向账目、四个工具、混合运行时、表格网格、DOCX 读取、评测体系。全部代码约 2.6 万行，与多来源融合相关的内容获取部分约 4 千行；本文的改动限于这一部分。

## 3. 提议：拟人的分工

一个人把 PDF 整理成 Markdown，大致四步：

| 人怎么做 | 系统里由谁做 | 现在由谁做 |
|---|---|---|
| **看**：一眼看出版面、阅读顺序、标题、公式、图，不去量字号比例 | 视觉模型看页面图，直接写出这一页 | 程序：检测器区域、几何规则、读数配对 |
| **能复制的就复制**：正文从 PDF 复制，字是准的；复制出来是乱码、公式复制不了的，照着页面重打 | 文字层逐行文字作为"可复制的原文"与页面图一起交给模型，由模型决定哪里用它 | 程序：两份读数交给五道门裁决 |
| **核对**：重打的地方数字对不对、有没有漏段 | 程序只做机械核对：页面上的字都有去处、数字不变、输出里的字页面上看得到；不一致列为待办 | 同（Q56 信号），但夹杂着裁决 |
| **拿不准就凑近看** | Agent 看图处理待办 | 同 |

**程序只保留三类东西**：

- 抽取出的事实：文字层的字符与位置、页面渲染图、检测器区域（只作提示）、本地识别结果、扫描引擎读数；
- 保证正确的核对；
- 记账与渲染。

**分层（指导 Q56 ⑤："不做每页都经服务读一遍"）**：人翻文档也是扫一眼，有问题才细看。

- 文字层干净、本地识别与文字层一致的页照旧处理。语料里这类页占多数，char_f1 已在 0.95 以上。
- 有证据的页才整页交模型：检测器标出公式、检测器看到图而页面没放图（画出来的图）、有映射不到字符的字形、本地识别与文字层不一致。
- 分流看的是"两份证据不一致"，不是"猜这是什么"。

**正视的三点**：

- **模型会认错字**：Q70 测过，通用视觉模型只看图读行间公式与标注的相似度 86.2，给它文字层字符后 87.5，扫描引擎 90.6；它会把 z′ 认成 ζ′、l 认成 L。所以"能复制的就复制"与"核对"不能省，这正是程序该做的部分。
- **每次结果不一样**：服务模型 gpt-6-luna 不接受 temperature，同样提示 4 次里照做 1–4 次；paper_chn01 的公式相似度只因多了几次模型调用就在 0.854 与 0.877 之间变动。评测要跑两次看波动，回放靠响应缓存。
- **费用与速度**：按页计费与计时，分流决定总量。

## 4. 实验要回答的设计问题

1. **输入**：页面图 + 文字层逐行文字（按阅读顺序，带行号）。另一臂再加扫描引擎的整页读数作第二份原文（公式的 LaTeX）：本轮实测最有效的组件之一就是"图 + 文字层 + 引擎读数"交模型编辑。
2. **输出格式**：这一页的块序列（段落、标题、列表、表格、行间公式、图的占位），每块给出类型。两种写法都试：
   - a. 模型直接写出每块的文字；
   - b. **引用行号**：能复制的块只写"复制第 12–15 行"，由程序把文字层原文放进去；复制不了的（公式、乱码、需要上下标的）才自己写。这样"能复制就复制"由程序执行，复制处的字符按构造就准确，核对只针对模型自己写的部分，账目也直接可算。风险是模型引错行号，以及一行里夹着行内公式时要整行重写。
3. **回到工作区**：每个输出块要落到文字层的行上，才能记账、给来源锚点、让 Agent 按块看图、做核对。写法 b 天然有；写法 a 要做字符序列对齐。实验量对齐覆盖率。
4. **核对与退路**：核对三条，都是 Q56 的守恒类：文字层的字在输出里（漏）；输出的数字在文字层或页面读数里（改数字）；输出的字页面上看得到（编造）。不过核对时，整页退回现有结果并列待办，还是逐块退——实验两种都算。
5. **表格与标题**：这两项现有流水线领先。模型整页写时是否变差，单独报告；若变差，表格区域保留现有网格、标题只把模型的 `#` 作证据交给现有标题步骤。
6. **扫描页与 Word**：扫描页的"可复制原文"是引擎读数（不精确），本实验只含 ocr01 一篇作观察。Word 没有页面图，不在本实验内。

## 5. 实验

### 5.1 假设

- **H1**：在有证据的页上，模型整页写（图 + 文字层）的 char_f1、关键内容错误、公式相似度，不差于规则版与补丁版。

- **H3**：写法 b（引用行号）比写法 a 丢字、改数字、编造都少，且账目完整。

### 5.5 事先写定的判定

- **采用**（重建内容步骤）：V 的最好臂对 M 与 R，在 6 篇 PDF 上同时满足——每篇 char_f1 不降超过两次运行之间的差异、公式文档平均上升；关键内容错误合计下降；表格 F1、标题 F1 不降（表格或标题保留现路径之后也算）；核对抓住人工发现的漏、改、编的绝大多数，未抓住的没有改数字一类；每篇服务费用不超过 $0.05。
- **不采用**：出现未被核对抓住的改数字或整段遗漏。
- **部分采用**：只在某一类页（公式页、画图页、乱码页）上满足时，只对这类页采用。
- C1：自己看图在"改对减改错"上明显更好、用时可接受，默认改为自己看；相当则维持委托；各有所长则只在需要看结构的待办类型上自己看（写在 Skill 里，不改工具）。
