# 读图能力摸底（model probe，2026-10-02）

## 1. 为什么做

ParserX 的解析效果很大程度上取决于服务模型读图读得怎么样。目前流水线里读图的服务模型：
- 读图、描述、回答 Agent 的提问：gpt-6-luna；
- 第二份读法：luna 加 DeepSeek（deepseek-flash）；
- Agent 改字时的重读：DeepSeek。

以后还会接入更多快速、低价的模型和新版本。每换一个就跑完整流水线要好几个小时。读图摸底把这件事缩成约 80 道小图题：
- 一个模型几十秒到几分钟跑完；
- 按能力分项打分；
- 和已测过的模型直接并排比较。

## 2. 能力怎么分

| 编号 | 能力 | 说明 |
|---|---|---|
| A1 | 逐字转写 | 印刷中英文，包括扫描模糊的 |
| A2 | 数字、单位、符号 | 小数点、负号、±、%、×、单位 |
| A3 | 上下标 | 化学式、单位指数、引用角标的位置 |
| A4 | 公式结构 | 分式、根号、求和、矩阵、对齐、编号，写成 LaTeX |
| A5 | 易混字形 | l/1、O/0、μ/u、K/k、ν/v、γ/r、H/μ |
| A6 | 忠实原件 | 原件的错字照抄，不按意思纠正、不补全 |
| A7 | 表格 | 行列结构、合并单元格、空格、单元格内容 |
| A8 | 图片理解 | 图表类型、图中的数值和标签、示意图里的关系 |
| A9 | 版面和阅读顺序 | 多栏、标题与正文、侧栏、图注 |
| A10 | 听指令 | 只输出要的内容，格式对，不加前言 |
| A11 | 稳定 | 同一张图读几次结果一致；没有空回答、截断、超时 |

每题可以标多项。A10、A11 不单独出题：每个回答都查 A10，另挑 10 道题各读 3 次算 A11。速度和费用另记，不算能力分。

## 4. 怎么考

**提示词和调用**：照抄流水线。

| 题型 | 提示词 | 附加内容 | 结构化输出 |
|---|---|---|---|
| 照抄、公式、整页、图中文字 | `second_reading.PROMPT` | 无 | 不要求 |
| 公式（可选的第二种做法，`--formula-editor`） | `formulas._EDITOR_PROMPT` | 文字层 A、扫描引擎读法 B 及两者的分歧 | 不要求 |
| 表格 | `review_table.md` | 流水线当前的读法（回放侧车里的表格），加"逐格核对字符、核对行列和合并"两条要查的问题 | `REVIEW_SCHEMA` |
| 图片理解 | `describe_figure.md`（语言按配置） | 图片附近的文字（`neighbors`，同流水线） | 描述的 schema |
| 回答问题 | `ask_image.md` | `问题：…` | 不要求 |

其余设置：
- **直接调服务**：`apply_overrides(load_config("configs/regression.yaml"), [use, effort, timeout])` 得到配置，再用 `OpenAICompatibleService.describe_image`。温度 0，不经过流水线的请求缓存。
- **不合格式时重问**：表格、图片的回答不是 JSON，照流水线的网关重问一次；第一次的回答留下，记为听指令的问题。
- **输出预算**：131072（含思考）。这是所有已配模型都接受的上限（GLM 的上限）。被截断的回答记为截断，不算答错。超时 1800 秒。
- **网络错误**：重试两次。仍失败的记为失败，不进缓存，下次再问。
- **缓存**：在 `eval_runs/model_probe/cache/<条目>/<强度>/`。键由模型、名称、强度、提示词、附加内容、预算、结构化设置、图片和第几次读共同决定。同键只请求一次，文件写完再换名，不会被同时写。
- **并发**：默认 8 个。
- **费用**：用配置里的价格表。没有自己价格的模型（gpt-6.1-sol）按它所在条目的模型（gpt-6-sol）估。

## 5. 怎么评分

全部自动；判不准的列在报告的"请人看的"里。

**照抄类**（照抄、陷阱、字形、图中文字、整页）：
- **要求的写法**：用 `content.select._placed` 得到"字符＋上下标"序列，同一个字的上下标先后统一（`δ^{r}_{ik}` 和 `δ_{ik}^{r}` 一样）。
  1. 把回答和参照对齐，取出回答里对应 `at` 的那一段；
  2. 用 `_shows` 判断这一段写出了参照独有的字；
  3. `want` 的每个字都在，误读写法独有的字不在，`at` 至少一半在。

  `at` 的位置靠在原文里插入两个标记字符再找回，所以数学式里的一处也能准确定位。
- **符号和带重音的字**（≥、～、Benoît）：规范化后看包含不包含。规范化包括 NFKC、半角，LaTeX 符号命令换成字符，去掉数学标记和空白。
- **陷阱**：分三种结果——照印的写、按意思改了、写成别的。判法同上，两个方向各判一次。
- **整块**：字母数字（含汉字）按顺序的 F1。截图边上露出的半行、页面装饰，回答里多出来的不扣分。另算只看数字的 F1、带上下标的 F1。
- **引擎读错的 9 块**：第一处要求的写法就是读错的那一处。另按流水线第二份读法的规则（`second_reading.disagrees`）统计：
  - 抓到：和引擎不同，且这一处写对；
  - 误报：16 块引擎读对的块里报出不同。

**公式**：
- `eval.formulas.compute_formula_metrics` 的相似度。回答里没有 `$$` 时，把它的数学部分当成一个独立公式；
- 矩阵元素是否在原位：新增 `parserx/eval/matrices.py`，从统一评测器移植，附测试；
- 能否排版：`content.latex.problems`。

**表格**：
- `eval.tables.compute_table_metrics` 的单元格 F1；
- 同时报模型拿到的"当前读法"本身的 F1，看复核是加分还是减分。

**图片理解**：
- 要点召回：类型字段也算一条，每条要点按关键词组判断；
- 编造：说明里出现图上没有的数字（前面带"约"的估读不算），或列为"图上没有"的名称；
- 得分 = 召回；有编造的减半。

**整页**：
- 阅读顺序：`eval.order.compute_order_metrics` 的 tau，负数按 0 计；研报页的侧栏和主栏分开算，侧栏放前放后都不扣分；
- 字符 F1；
- 页上有表格的另算表格 F1。

**回答问题**：
- 规范化后整句等于一个接受的答案，算对；
- 或者接受的答案出现、且出现在任何不接受的答案之前，也算对。

**听指令（A10）**：查每个回答有没有以下问题——
- 空回答；
- 前言（"以下是…"）；
- 末尾的说明（"注：…"）；
- 参照没有却加了代码围栏；
- 不合格式，或第一次回答不合格式；
- 问题答得太长（超过 60 字）。

A10 = 没有任何问题的回答的占比。

**汇总**：
- 每题对它计的每项能力给一个 0–1 的分：
  - 有那项能力的要求写法或陷阱，就用它们；
  - 否则用那项能力对应的量：A1 整块 F1、A2 数字 F1、A3 带上下标的 F1、A4 公式相似度、矩阵和排版的平均、A7 表格 F1、A9 阅读顺序。
- 每项能力的分 = 计这项能力的各题得分的平均，同时报题数；
- 总分 = 各题得分的平均，每题得分是它所计各项能力分的平均；
- A11 = 稳定性题 3 次读法的字母数字（含上下标）一致的占比，另报 3 次得分也一致的占比；
- 失败、截断、空回答单独列出，不计入能力分；
- 另报：
  - 中位用时、总用时、总费用、每 100 题（首读）的费用；
  - 输出（含思考）超过流水线现用预算的回答数。流水线现用预算：第二份读法 32768、表格复核 4096、图片说明 300、提问 1024。

## 6. 用法

```bash
uv run --frozen python scripts/model_probe.py --model deepseek-flash --effort medium
uv run --frozen python scripts/model_probe.py --model gpt-6-sol --name gpt-6.1-sol --effort low
uv run --frozen python scripts/model_probe.py --model gpt-6-luna --effort low --rescore
uv run --frozen python scripts/model_probe.py --compare eval_runs/model_probe/<结果目录> …
```

- 可选参数：
  - `--cases`：题目目录；
  - `--repeat`：稳定性题的读次，默认 3；
  - `--only A4,A7`：只问计这些能力的题；
  - `--rescore`：只用缓存重新评分，不请求；
  - `--formula-editor`：公式另用编辑提示词问一遍；
  - `--workers`：并发数；
  - `--budget`：输出预算。
- 结果在 `eval_runs/model_probe/<日期>_<条目>_<强度>/`（不进 git）：
  - `answers.jsonl`：每次请求的原始回答、用量、用时、失败；
  - `scores.json`：每题、每项能力的得分；
  - `report.md`：中文报告，和其他已跑模型并排。
- `--compare` 把几次结果并排成一张表，另存为 `eval_runs/model_probe/compare_<日期>.md`。
- 代码：`scripts/model_probe.py`，测试 `tests/test_model_probe.py`（假服务，离线）、`tests/test_eval_matrices.py`。

### 7.1 DeepSeek 的温度、思考强度与稳定性（2026-10-02，用户提问）

- 常错的字形：化学段落的 ν̃max 写成 `\tilde{v}`（四处全错），上标 l 读成 1，模糊的 μ/η。

**"不稳定"是服务端挂起，不是回答不稳**：
- 约 960 次请求里，有 5 次发出后服务端一直不回，都在开着思考的档；
- 重试后几十秒到两分钟就正常回来，输出长度正常；
- 其他模型上千次请求没有一次这样。

摸底时为等长思考把超时放到 30 分钟，所以一次挂起就拖半小时；流水线默认 180 秒超时加重试，影响只有几分钟。豆包这一轮最慢的正常回答约 130 秒，单次超时设 5 分钟就够：摸底工具新增 `--timeout`（不进缓存键），实验脚本同。

**回答本身最稳**：同一处改字三次判定，low 57/57、none 56/57 一致；同一张图三次读法，low 84/96 完全一致，都是所有模型里最高。

## 8. 以后怎么接入新模型

1. 在个人配置 `~/.config/parserx/config.yaml` 的 `models` 里加一个条目：端点、密钥引用、接口、接受的思考强度、结构化输出。写法见 `docs/v2_model_config.md` §6–7。
2. 在 `scheduling.prices` 里补它的价格。没有价格，报告里的费用记为未知。
3. 用 `scripts/check_services.py --model <条目>` 核对条目。
4. 跑一条命令：`uv run --frozen python scripts/model_probe.py --model <条目> --effort <强度>`。报告自动和已跑的模型并排；需要时再 `--compare`。

题目要改，就改 `build_cases.py`、升版本号重新生成，并在本文 §3 的版本记录里写明。旧结果要按新版本重新评分（`--rescore`，不花钱）。

## 9. 局限

- **样本小**：每项能力 6–43 题，差几分不算显著。A9、A10 现在几乎全满分，区分不出模型。
- **表格题考的是"复核"**（给了当前读法），不是从零读表；10 张里有 5 张当前读法已经全对。
- **图片说明只有 50–100 字**，要点按关键词判，可能漏判换了说法的要点。所以图片题的回答都列在报告里请人看。
- **稳定性只有 10 题各 3 次**。
