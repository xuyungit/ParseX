# 输入与输出：分解（2026-09-28，Q116–Q119 按建议；待用户确认本分解）

**目标**：
- **输出**：用户拿到的就是 Markdown 和它引用的图片，内容读得懂；工作信息（摘要、sidecar）按需才写。
- **输入**：除了本地文件和目录，也能直接给网址、递归处理目录、处理图片文件。

## 1. 事实

### 1.1 输入

- **已支持**：一次多个文件或目录。目录只取当前一层的 PDF、DOCX、DOC，跳过隐藏文件和 `~$` 临时文件。`.doc` 在临时目录里经 LibreOffice 转成 `.docx`（`content/convert.py`）。
- **不支持**：
  - 网址；
  - 子目录；
  - 图片文件：`tools/init.py` 按后缀判断，其他后缀报 "unsupported input type"。
- **输出目录的名字**：
  - 单个输入：`-o` 或 `./output/<文件名去后缀>/`；
  - 多个输入：`<-o 或 ./output>/<文件名去后缀>/`；
  - **同名会冲突**：`report.pdf` 和 `report.docx`，或两个目录里的同名文件，会写进同一个目录。

### 1.2 输出

- **写出了什么**：`render/export.py` 每篇都写四样：
  - `<名称>.md`；
  - `images/`：提取出的全部图片。扫描表单那篇有 9 个文件，Markdown 只引用 3 个；
  - 摘要 `<名称>.json`：1–13 KB；
  - sidecar `<名称>.blocks.json`：是 Markdown 的 30–50 倍，patent01 1.3 MB、paper_chn02 1.6 MB。
- **写在哪里**：混合方案先在工作目录里导出完整的包，再复制到输出目录（`runtimes/hybrid.py` 的 `_install`）。评测的固定流水线也经过同一个导出步骤，并读取 sidecar。所以 sidecar 在内部仍要写，只是不一定交给用户。
- **Markdown 里的内部写法**：
  - 图片描述块：首行是 `> [图片语义] other`（类型名是英文内部词），每项后面带证据等级"（可见）""（推断）""（估读）"；
  - 图片的替代文字是类型名（`other`、`chart: …`）；
  - 扫描页图像的替代文字是"扫描图像"；
  - 这些中文标签不管文档是什么语言，都是中文。
- **评测怎样剔除**：`eval/normalize.py` 剔除紧跟图片行的任何引用块，不看首行写什么。所以描述块改写法不影响文字指标。页码注释 `<!-- PAGE n -->` 作为 HTML 注释也被剔除。
- **识别失败的内容**：不在 Markdown 里出现，只在控制台和摘要的 `missing` 里列出。

## 2. 范围

**做**：
- 默认输出与按需输出（Q116）；
- 缺失提示（Q117）；
- 图片说明的写法（Q118）；
- 网址、递归目录、图片输入，以及同名处理（Q119）；
- README。

**不做**：PPTX、XLSX、HTML 输入；标准输入（stdin）。

## 3. 工作项

| 项 | 内容 | 验收 |
|---|---|---|
| IO1 默认输出 | 工作目录里照旧导出完整的包。复制到输出目录时只给 `<名称>.md` 和 Markdown 引用的图片。<br>`--report`：另写摘要 `<名称>.json`。<br>`--sidecar`：另写 `<名称>.blocks.json`。<br>`--json`：摘要照旧打到 stdout。<br>导出本身（`write_export`）的 `images/` 也只放渲染出的图片。控制台的"其余文件"一行按实际写出的文件列出。评测、L1、实验脚本走内部导出，不受影响 | L0；输出目录的文件清单；L1 PASS |
| IO2 图片说明 | 描述块改为读者看得懂的写法：<br>首行"图片说明"加类型的中文名（示意图、图表、照片、印章、图片），后面是它的名称或标题；<br>各项不再带"（可见）"，估计值和推断按 Q121 标注；<br>替代文字用一句话概述（截短）；<br>仍是紧跟图片行的引用块，评测照旧剔除。<br>`<!-- PAGE n -->` 保留 | L0（渲染快照）；全语料文字指标逐篇不变 |
| IO3 缺失提示 | 识别失败或预算跳过的块，在原位置输出一行，例如"> 〔未识别〕第 3 页：一处扫描内容未能识别（扫描引擎未配置）"。原因取自 `missing` 的记录，用读者的话写。评测新增一条规则，剔除这种行，文字指标不受影响 | L0；用"未配置扫描引擎"的扫描件复现，提示出现在原位置 |
| IO4 输入 | ① 网址（http、https）：下载到临时目录，有大小上限和超时（Q123）；格式按文件内容判断（PDF、DOCX、DOC、图片的文件头），不按网址后缀；名称取自服务器给的文件名或网址路径。<br>② `-r/--recursive`：递归目录，输出按相对路径镜像（`<-o>/<子目录>/<名称>/`）。<br>③ 图片文件（JPG、PNG、TIFF、BMP、WebP）：在临时目录里用 PyMuPDF 转成 PDF，一张图一页，多页 TIFF 每帧一页，作为扫描页交扫描引擎。<br>④ 同名输入按 Q122 区分 | L0：用本机临时起的 HTTP 服务测网址，不下载外部文件；递归目录；三种图片格式；同名 |
| IO5 冻结 run 与说明 | IO2、IO3 改变了 Markdown：两个冻结 run 按 Q124 重新冻结。README（中英）改写"使用""输出"两节 | 新冻结 run 回放 PASS；分数与旧冻结 run 逐篇相同，只有输出变了 |

## 4. 顺序

IO1 → IO2 → IO3 → IO4 → IO5。
- IO2、IO3 都改 Markdown 渲染，做完后一起重新冻结一次。
- 每项完成后跑 L0、L1，提交一次。

## 5. 退出条件

- **默认输出**：输出目录里只有 Markdown 和它引用的图片；`--report`、`--sidecar` 按需写出；评测、L1 不受影响。
- **Markdown**：没有英文类型名和"（可见）"这类内部写法；识别失败的地方有可见的提示；评测剔除它们，全语料文字、表格、标题分数逐篇与改动前相同。
- **输入**：网址、递归目录、图片文件都能处理；同名输入不互相覆盖。
- **测试**：L0、L1 通过；重新冻结后的两个 run 回放 PASS。

## 6. 待决问题

- **Q120 Markdown 里新加的文字用什么语言。**
  - **问题**：图片说明、缺失提示都是新加的文字。
  - **建议**：按文档语言，正文以中文字符为主就用中文，否则用英文；不跟控制台的界面语言。Markdown 是给读这篇文档的人和模型看的。
- **Q121 图表的证据等级怎么标。**
  - **建议**：看得见的不标；估计值（从坐标读出的数）前加"约"（英文 "~"）；推断的标"（推断）"；不明的不写。
- **Q122 同名输入怎么区分。**
  - **建议**：先到的用原名，后到的目录名加 `-2`、`-3`；控制台照常显示每篇写到了哪里。
- **Q123 网址下载的限制。**
  - **建议**：只接受 http 和 https；大小上限默认 200 MB，超时 120 s，都可在配置里改；按文件内容判断格式，认不出就报错。
- **Q124 冻结 run 怎样重新冻结。**
  - **建议**：两个冻结 run 都从各自的缓存重放，不发新请求。这次只有渲染变了，模型的响应都在缓存里。
