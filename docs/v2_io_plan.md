# 输入与输出：分解（2026-09-28，Q116–Q119、Q122–Q124 按建议；Q120、Q121 按用户意见，IO2 改为重新设计图片说明；IO1–IO5 已完成，Q125 待决）

**目标**：
- **输出**：用户拿到的就是 Markdown 和它引用的图片，内容读得懂；工作信息（摘要、sidecar）按需才写。
- **输入**：除了本地文件和目录，也能直接给网址、递归处理目录、处理图片文件。

## 1. 事实

### 1.1 输入

- **已支持**：一次多个文件或目录。目录只取当前一层的 PDF、DOCX、DOC，跳过隐藏文件和 `~$` 临时文件。`.doc` 在临时目录里经 LibreOffice 转成 `.docx`（`content/convert.py`）。
- **不支持**：
  - 网址；
  - 子目录；
  - 图片文件：`tools/init.py` 按后缀判断，其他后缀报 "unsupported input type"。
- **输出目录的名字**：
  - 单个输入：`-o` 或 `./output/<文件名去后缀>/`；
  - 多个输入：`<-o 或 ./output>/<文件名去后缀>/`；
  - **同名会冲突**：`report.pdf` 和 `report.docx`，或两个目录里的同名文件，会写进同一个目录。

### 1.2 输出

- **写出了什么**：`render/export.py` 每篇都写四样：
  - `<名称>.md`；
  - `images/`：提取出的全部图片。扫描表单那篇有 9 个文件，Markdown 只引用 3 个；
  - 摘要 `<名称>.json`：1–13 KB；
  - sidecar `<名称>.blocks.json`：是 Markdown 的 30–50 倍，patent01 1.3 MB、paper_chn02 1.6 MB。
- **写在哪里**：混合方案先在工作目录里导出完整的包，再复制到输出目录（`runtimes/hybrid.py` 的 `_install`）。评测的固定流水线也经过同一个导出步骤，并读取 sidecar。所以 sidecar 在内部仍要写，只是不一定交给用户。
- **Markdown 里的内部写法**：
  - 图片描述块：首行是 `> [图片语义] other`（类型名是英文内部词），每项后面带证据等级"（可见）""（推断）""（估读）"；
  - 图片的替代文字是类型名（`other`、`chart: …`）；
  - 扫描页图像的替代文字是"扫描图像"；
  - 这些中文标签不管文档是什么语言，都是中文。
- **评测怎样剔除**：`eval/normalize.py` 剔除紧跟图片行的任何引用块，不看首行写什么。所以描述块改写法不影响文字指标。页码注释 `<!-- PAGE n -->` 作为 HTML 注释也被剔除。
- **识别失败的内容**：不在 Markdown 里出现，只在控制台和摘要的 `missing` 里列出。

## 2. 范围

**做**：
- 默认输出与按需输出（Q116）；
- 缺失提示（Q117）；
- 图片说明的写法（Q118）；
- 网址、递归目录、图片输入，以及同名处理（Q119）；
- README。

**不做**：PPTX、XLSX、HTML 输入；标准输入（stdin）。

### 3.1 IO2：图片说明重新设计（用户意见，2026-09-28）

**用户的要求**：
- 图片说明是给读文档的人和模型看的，一两句话就够，一般不超过 50 字，最多 100 字；
- 可以用"约""推断"这类词；
- 逐张细读是另一个工程；
- 图表怎么读、照片怎么读，要从提示词整体考虑，同时控制篇幅和耗时。

**现状**（luna 全语料 66 段描述）：
- 渲染出的描述块中位数 122 字，90% 分位 340 字，最长 724 字（text_pic02 的截图把可见文字全列了出来）；
- 其中一句话概述（summary）本身中位数只有 37 字，多出来的是结构化清单：可见文字、节点和连线、数据序列、每项的证据等级；
- 这些清单只用来渲染 Markdown，以及在摘要里写示意图的类型；图中假表改为文字（T5）只看类型。

**设计**：
- **只要两样**：`type`（图表、示意图、照片、印章、截图、其他）和 `caption`（一两句话，一般不超过 50 字，最多 100 字）。不再要清单，不再逐项标证据等级。
- **按类型怎么读**：
  - **图表**：说清画的是什么量随什么变化，再加一句最主要的结论（趋势、最大最小、对比），比如"柱状图：2019–2023 年营收，逐年上升，2023 年约 12 亿元"。不逐点朗读数据；估读的数用"约"。
  - **示意图**：画的是什么，主要组成或流程的走向。
  - **照片**：拍的是什么；看得出场景、状态的，简短一提。
  - **截图**：哪个软件、哪个界面，做什么用。
  - **印章、二维码、标志**：是谁的、是什么。
- **图里的文字不抄**：扫描引擎已经把图中文字转写在图片之后，说明里不重复。
- **其他约定**：
  - 图里没有的数不编；看不清的不写；推断的内容可以用"可能""推断"。
  - 说明文字的语言：默认中文，`--lang en` 时写英文（Q120）。`--lang` 同时决定控制台和 Markdown 里新加文字的语言。
- **Markdown 的写法**：
  - 图片行的替代文字是类型名，如 `![图表](images/…)`；
  - 紧跟一行 `> 图片说明：……`；
  - 同一句话不写两遍（§4.5 的原则）。
- **篇幅与耗时**：输出只有一两句话，输出 token 预算定为 300，思考强度 low。对照现在的提示词，在全语料上量说明长度、输出 token、单张用时与费用，并挑十几张并排给用户看。
- **范围**：
  - 服务模型的看图问答、表格重读不在此列。
  - Agent 的 `view_source` 选"描述"时，也返回这个简短说明。
- **代价**：提示词变了，缓存里没有新响应。重新冻结时，这部分要发新请求（全语料约 80 个，luna 约 $0.03），不能像 Q124 那样全从缓存重放。

## 5. 退出条件

- **默认输出**：输出目录里只有 Markdown 和它引用的图片；`--report`、`--sidecar` 按需写出；评测、L1 不受影响。
- **Markdown**：没有英文类型名和"（可见）"这类内部写法；识别失败的地方有可见的提示；评测剔除它们，全语料文字、表格、标题分数逐篇与改动前相同。
- **输入**：网址、递归目录、图片文件都能处理；同名输入不互相覆盖。
- **测试**：L0、L1 通过；重新冻结后的两个 run 回放 PASS。
