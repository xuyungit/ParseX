# 输入与输出：分解（2026-09-28，Q116–Q119、Q122–Q124 按建议；Q120、Q121 按用户意见，IO2 改为重新设计图片说明；IO1–IO5 已完成；IO6 图片按用途处理，分解见 §7，待确认）

**目标**：
- **输出**：用户拿到的就是 Markdown 和它引用的图片，内容读得懂；工作信息（摘要、sidecar）按需才写。
- **输入**：除了本地文件和目录，也能直接给网址、递归处理目录、处理图片文件。

## 1. 事实

### 1.1 输入

- **已支持**：一次多个文件或目录。目录只取当前一层的 PDF、DOCX、DOC，跳过隐藏文件和 `~$` 临时文件。`.doc` 在临时目录里经 LibreOffice 转成 `.docx`（`content/convert.py`）。
- **不支持**：
  - 网址；
  - 子目录；
  - 图片文件：`tools/init.py` 按后缀判断，其他后缀报 "unsupported input type"。
- **输出目录的名字**：
  - 单个输入：`-o` 或 `./output/<文件名去后缀>/`；
  - 多个输入：`<-o 或 ./output>/<文件名去后缀>/`；
  - **同名会冲突**：`report.pdf` 和 `report.docx`，或两个目录里的同名文件，会写进同一个目录。

### 1.2 输出

- **写出了什么**：`render/export.py` 每篇都写四样：
  - `<名称>.md`；
  - `images/`：提取出的全部图片。扫描表单那篇有 9 个文件，Markdown 只引用 3 个；
  - 摘要 `<名称>.json`：1–13 KB；
  - sidecar `<名称>.blocks.json`：是 Markdown 的 30–50 倍，patent01 1.3 MB、paper_chn02 1.6 MB。
- **写在哪里**：混合方案先在工作目录里导出完整的包，再复制到输出目录（`runtimes/hybrid.py` 的 `_install`）。评测的固定流水线也经过同一个导出步骤，并读取 sidecar。所以 sidecar 在内部仍要写，只是不一定交给用户。
- **Markdown 里的内部写法**：
  - 图片描述块：首行是 `> [图片语义] other`（类型名是英文内部词），每项后面带证据等级"（可见）""（推断）""（估读）"；
  - 图片的替代文字是类型名（`other`、`chart: …`）；
  - 扫描页图像的替代文字是"扫描图像"；
  - 这些中文标签不管文档是什么语言，都是中文。
- **评测怎样剔除**：`eval/normalize.py` 剔除紧跟图片行的任何引用块，不看首行写什么。所以描述块改写法不影响文字指标。页码注释 `<!-- PAGE n -->` 作为 HTML 注释也被剔除。
- **识别失败的内容**：不在 Markdown 里出现，只在控制台和摘要的 `missing` 里列出。

## 2. 范围

**做**：
- 默认输出与按需输出（Q116）；
- 缺失提示（Q117）；
- 图片说明的写法（Q118）；
- 网址、递归目录、图片输入，以及同名处理（Q119）；
- README。

**不做**：PPTX、XLSX、HTML 输入；标准输入（stdin）。

### 3.1 IO2：图片说明重新设计（用户意见，2026-09-28）

**用户的要求**：
- 图片说明是给读文档的人和模型看的，一两句话就够，一般不超过 50 字，最多 100 字；
- 可以用"约""推断"这类词；
- 逐张细读是另一个工程；
- 图表怎么读、照片怎么读，要从提示词整体考虑，同时控制篇幅和耗时。

**现状**（luna 全语料 66 段描述）：
- 渲染出的描述块中位数 122 字，90% 分位 340 字，最长 724 字（text_pic02 的截图把可见文字全列了出来）；
- 其中一句话概述（summary）本身中位数只有 37 字，多出来的是结构化清单：可见文字、节点和连线、数据序列、每项的证据等级；
- 这些清单只用来渲染 Markdown，以及在摘要里写示意图的类型；图中假表改为文字（T5）只看类型。

**设计**：
- **只要两样**：`type`（图表、示意图、照片、印章、截图、其他）和 `caption`（一两句话，一般不超过 50 字，最多 100 字）。不再要清单，不再逐项标证据等级。
- **按类型怎么读**：
  - **图表**：说清画的是什么量随什么变化，再加一句最主要的结论（趋势、最大最小、对比），比如"柱状图：2019–2023 年营收，逐年上升，2023 年约 12 亿元"。不逐点朗读数据；估读的数用"约"。
  - **示意图**：画的是什么，主要组成或流程的走向。
  - **照片**：拍的是什么；看得出场景、状态的，简短一提。
  - **截图**：哪个软件、哪个界面，做什么用。
  - **印章、二维码、标志**：是谁的、是什么。
- **图里的文字不抄**：扫描引擎已经把图中文字转写在图片之后，说明里不重复。
- **其他约定**：
  - 图里没有的数不编；看不清的不写；推断的内容可以用"可能""推断"。
  - 说明文字的语言：默认中文，`--lang en` 时写英文（Q120）。`--lang` 同时决定控制台和 Markdown 里新加文字的语言。
- **Markdown 的写法**：
  - 图片行的替代文字是类型名，如 `![图表](images/…)`；
  - 紧跟一行 `> 图片说明：……`；
  - 同一句话不写两遍（§4.5 的原则）。
- **篇幅与耗时**：输出只有一两句话，输出 token 预算定为 300，思考强度 low。对照现在的提示词，在全语料上量说明长度、输出 token、单张用时与费用，并挑十几张并排给用户看。
- **范围**：
  - 服务模型的看图问答、表格重读不在此列。
  - Agent 的 `view_source` 选"描述"时，也返回这个简短说明。
- **代价**：提示词变了，缓存里没有新响应。重新冻结时，这部分要发新请求（全语料约 80 个，luna 约 $0.03），不能像 Q124 那样全从缓存重放。

### 7.2 事实

- **现在的顺序**（`tools/process.py`）：
  1. 扫描路线（SCAN）、混合路线（MIXED）的图先转写；
  2. 没有转写的图写说明；
  3. 不确定路线（UNCERTAIN）的图，如果说明没带上本地读数里的字，再转写（守恒，P4-6）。
- **路线由版面检测决定**：看图中文字、图形的面积（`routing/image.py`），不知道图的用途。
  - 同一张下拉菜单截图因为字多，走扫描路线，被读成带合并格的表，也没有说明（text_pic02 第 11、12 页）。
- **全语料正文里显示的原始图片共 67 张**（冻结 run `2026-09-28_io_fixed_full`）：

  | 路线 | 张数 | 现在的处理 |
  |---|---|---|
  | FIGURE | 29 | 只写说明 |
  | SCAN | 13 | 12 张转写、不写说明（其中 patent01 公式图片 9 张） |
  | UNCERTAIN | 17 | 都写说明，其中 12 张也转写 |
  | MIXED | 8 | 写说明，也转写 |

- **渲染**：
  - 转写内容只有开头的 `<!-- 以下转录自上图 -->`，没有结尾，也没有文件名；
  - 扫描页只有 `<!-- PAGE n -->`，看不出这一页是识别出来的；
  - `eval/metrics.py`、`eval/text.py` 按 `<!-- PAGE n -->` 的原样解析页标记。
- **页面比对**（`reading/compare.py`）：已经把"显示出的图片"当作其中文字的去处。所以图画类不转写，不会被当成漏字。
- **T5**（`tables/drawings.py`）：把图表、示意图里读出的表改为文字。图画类不再转写后，它就没有对象了。
- **`split_frames` 的缺陷**：切出的块丢了与图片的 CONTAINS 关系（Q125 实验发现），渲染和统计都认不出它们来自图片。
- **看原件时的"描述"**：Agent 用 `view_source` 看原件时可以选"描述"，经 `edit_draft adopt` 采用，用的是同一套说明。
- **实验材料 real_doc03**：87 页 DOCX，149 张图，不在标注语料里，本地路径见 memory。其中有：

### 7.3 设计

1. **两类图**：由服务模型看整张图和附近文字来判断。判断的是用途，不是媒介。同一张订单页，放在操作手册里是界面，放在报销材料里是票据。
   - **内容类**（新类型 `content`）：图上的字就是要传达的内容。包括票据发票、证书证照、文档或合同页面、表格、成段文字、代码或命令行输出、公式。
   - **图画类**：`screenshot`（展示界面）、`chart`、`diagram`、`photo`、`seal`、`other`。
   - **提示词里的判据**：
     - 图的用途是承载读者需要引用或检索的具体信息（金额、日期、编号、账号、条款、成段正文），判为内容类；
     - 展示界面、外观、场景、关系、趋势，判为图画类；
     - 拿不准时判为图画类：原图保留，关键信息在说明里点到。
2. **顺序：先写说明，再转写**。
   - 正文里显示的原始图片（装饰图除外）都先写说明、判类型。
   - 只转写内容类。
   - 删去守恒转写（第 3 步）和 T5：图画类的字由显示出的原图承接。
   - **回退**：服务模型未配置或请求失败时，按现在的路线处理（扫描、混合路线转写），不丢字。
3. **图画类的说明**：
   - 在现在的提示词上加三点：
     - 箭头、框、圈标出的是什么；
     - 关键文字、关键数字照图中原样写；
     - 截图写清是哪个界面、做什么。
   - 篇幅不变：一般不超过 50 字，最多 100 字。
   - **数字核对（信号，不是裁决）**：说明里的数字串要在这张图的本地读数里找得到。找不到的列入待办，由 Agent 看图核对（重新描述或驳回）。没有 Agent 时，在摘要里列出，不改说明。
4. **内容类的呈现**（用户确认的写法，2026-09-28）：原图不显示，转写放进引用块。引用块第一行是标签行：`〔图片识别〕`、判类型时写的一句说明、"原图"链接。
   ```markdown
   <!-- parserx:image-text src="images/a-cfcb42df.png" page=3 -->
   > **〔图片识别〕** 华通智能装备股份有限公司2024年度财务情况说明书　[原图](images/a-cfcb42df.png)
   >
   > **华通智能装备股份有限公司**
   >
   > 一、企业概况 ……
   >
   > | 项目 | 本期金额（元） | … |
   > | --- | --- | … |
   <!-- /parserx:image-text -->
   ```
   - 与图画类一致：凡是引用块都表示"来自图片"。图画类是原图加 `> 图片说明：…`。
   - 图片里识别出的标题在引用块里加粗，不进文档的标题层级。
   - 表格（包括 HTML 表格）每行加 `> ` 前缀。
   - 英文版的标签是 `**[Text from image]**`。
   - **何时这样呈现**：
     - 转写成功，且经本地读数核对没有漏字：照上面的写法；
     - 转写有漏字：原图也显示在引用块之前；
     - 转写失败：原图显示，并按 IO3 留缺失提示。
   - 显示与否只在渲染时决定，块的状态不变，去向检查不受影响。
5. **痕迹标记**：用固定的英文格式，不随 `--lang` 变，给下游程序看。
   - 前后一对注释 `<!-- parserx:image-text src="…" page=n -->` 与 `<!-- /parserx:image-text -->`。说明已在可见的标签行里，注释只带 `src` 和 `page`。DOCX 没有页码，就不写 `page`。
   - 原图文件照样放进 `images/`：标签行的链接本来就引用它，导出照常复制。
   - 扫描页写成 `<!-- PAGE 3 scanned -->`，评测里的两处页标记正则一并改。
   - 取代 `<!-- 以下转录自上图 -->`。表格单元格里切出的图，其标记 `<!-- 以下是上方〔图 n〕处的图片 -->` 不变。
   - **评测**：只把引用块里的转写算进文字分数，去掉标签行和 `> ` 前缀。原来"剔除紧跟图片行的引用块"的规则对图画类照旧。
6. **修 `split_frames`**：切出的块继承原块与图片的 CONTAINS 关系。
7. **Agent**：
   - 任务说明与工具参考随之改："描述"返回新类型；待办新增"说明里的数字在图中读不到"。
   - Agent 采用的描述若把图改判为内容类，按第 2 步补转写。
