# 模型能力比较：分解（2026-09-27，用户确认 2026-09-28，Q101–Q105 按建议）

**目标**：比较 gpt-6-luna、deepseek-flash、glm-5.3-flashx 在两个角色上的表现，为各角色选模型提供依据。
- **Agent 主控**：驱动自己的循环。
- **服务模型**：`services.vlm`。

gpt-6-sol 已测过（s5、d1 的 Codex），费用高，不再测，只作参照。

**前提**：先把各模型接口上的细微差异写进配置（Q100 决定一），再比较。否则比出来的差别，一部分是参数没配对造成的，不是模型能力。

**费用**：两个角色都按 API 计费，由用户这次指定。估计见 §3。

## 1. 事实

### 1.1 两个角色各做什么

- **Agent 主控**：
  - 自己的循环（`runtime.agent.engine: loop`）用 `runtimes/models.py` 的两种适配器（Responses、Chat）与模型对话。
  - 工具、任务说明、Skill 与 Codex 共用。
  - 过程指标都有记录：调用、无效请求、被拒、token 与缓存、用时、费用。
- **服务模型**：v2 只有一个服务模型 `services.vlm`（没有单独的 LLM），做四件事。

  | 任务 | 何时 | 思考强度（`tools.*`） | 对分数的影响 |
  |---|---|---|---|
  | 图片描述与图中文字（`describe_figure`） | 固定流水线 | low | 描述不计入文字指标（Q17）；描述里的图表类型决定图中读出的"表"是否改为文字（T5） |
  | 公式编辑（`formulas`） | 固定流水线，公式页 | low | 计入 char_f1（paper_chn01、paper_chn02 等） |
  | 看图回答（`view_source` answer） | Agent 调用 | low | 间接：Agent 据此修改 |
  | 表格重读（`view_source` table） | Agent 调用 | 服务默认（none） | 间接：经复核门槛采用 |

### 1.2 各模型接口的差异

来源：[v2_model_config.md](v2_model_config.md) §1.1，以及今天的探测。

| | gpt-6-luna | deepseek-flash | glm-5.3-flashx |
|---|---|---|---|
| 接口 | Responses | Responses、Chat；循环用 Chat | 只有 Chat（Responses 404，服务自动回退，每个服务实例多一次请求） |
| temperature | 拒绝 | 接受 | 接受 |
| 思考强度 | none / low / medium | 未逐值测过 | 只接受 low / high / max；none 会被拒，报错是中文，服务认不出、不会自动去掉 |
| 思考内容 | 加密，Responses 交回 | `reasoning_content`，工具循环里交回（aada802） | 未测 |
| 图片 | 可以 | **可以**（今天探测：读出了样张的文字） | **可以**（同上） |
| 结构化输出（json_schema / json_object） | 支持 | 未测 | 未测；Q100 的描述测试是把 schema 写在提示里 |
| 价格（每百万 token） | 0.10 / 缓存 0.01 / 输出 0.50 | 0.30 / 0.006 / 1.20（高峰） | **配置里没有**，费用显示"unpriced" |

- **结构化输出**：图片描述和表格重读都要求 JSON。服务会从 json_schema 退到 json_object，再退到不约束，但判断依据是认出报错。这和 effort 一样：别家的报错认不出，就不会退。所以结构化输出也是要写进模型条目、要探测的差异。
- **配置现状**：
  - `parserx.yaml` 只配了 luna 一个服务模型。
  - 换模型要借 `.env` 的后缀组（`_D`、`_G`），外加实验用的覆盖参数；循环另有一套 `runtime.agent` 字段。
  - Q100 的 `models` + `use` 设计写好了，未实施。

### 1.3 以前的结果

- **Agent，luna**：s5，5 篇，自己的循环。
  - heading 0.570，gpt-6-sol 0.678，固定流水线 0.513。
  - Agent 标价 $0.046，sol 循环 $0.94。
  - 5 篇全部交稿，待办全部处理。
- **Agent，DeepSeek**：d1，9 篇。
  - 质量与 Codex 相当：heading 0.776 对 0.785，角色 0.831 对 0.826。
  - $0.63，用时多三分之一。
  - DOCX 的大纲核对不如 Codex 细。
- **Agent，GLM**：没测过。
- **服务模型**：Q40 之后生产只用 luna，没有做过对比。旧版 qwen（s6）的标题较弱，与本题无关。
- **波动**：同一篇文档、同一个模型，Agent 的做法每次不同。例如 paper_chn02 在 g5 里重读了表 5，在 g5b 里没有重读。所以单次运行的逐篇差别不能作结论。

## 5. 退出条件

- **接口**：
  - 三个模型都能担任两个角色；
  - 没有按服务商写的代码；
  - 被拒的参数和结构化输出都由条目决定，不靠认报错。
- **不退步**：生产配置（luna）的输出与指纹不变，两个冻结 run 回放 PASS，L0、L1 通过。
- **比较**：两个角色各有一张表，逐篇与汇总都有，过程指标齐全；Agent 角色每个组合 2 次。
- **结论**：报告给出各角色的推荐和理由。默认模型是否改动，由用户决定。
