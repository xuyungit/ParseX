# 表格的待办信号：分解（2026-09-27，用户确认，Q93–Q95 按建议）

**目标**：程序修不好的表格，要有一条待办把 Agent 引到那张表上，并说清该用什么工具（区域重读、`adopt`、`set_cells`）。T7 的结论是：Agent 只在问题摆在眼前时修表格；外框里的几张表、图中的假表、丢失的表头都没有待办指向，它也就没有发现（[报告](../eval_reports/2026-09-27_tables.md) §2）。

**费用**：信号是程序对已有读数的整理，全部离线（冻结 run 回放），输出的 Markdown 不变；Agent 验证用 Codex（包月）。

**其他事实**：
- **拆开的外框没有各自的位置**：T3 拆出的几张表共用整个外框的区域（unseen_pdf_tables01 第 4–6 页各 3–4 张表同一个框），格子也不带坐标。所以区域里的一行说不出属于哪一张，对其中一张做区域重读，读到的是整个外框。
- **死的待办种类**：`table_uncertain` 已定义，但没有代码写入（`review_table` 去掉之后就没有了），只剩枚举和界面文案。
