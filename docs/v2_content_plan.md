## 5. A 线：原生页的内容获取按区域

### 5.1 单位

- **行间公式**：页面上的一个区域，一个 `FORMULA` 块。区域证据三种，都已有：检测器 display_formula 区域（免费，不完整）；引擎整页读数的公式项（有内容、覆盖好，一篇一次批量请求）；文字层字形（私用区字符、5.9 磅的上下标 span、矢量线条处的空白）。区域 = 引擎公式项的框 ∪ 与之重叠的检测器公式区域 ∪ 中心落在其中的文字层行（含整个落在框内的碎片，如撇号）。
- **行内公式**：段落（现在的 `_passages` 配对）。
- **图片**：检测器 image/chart/seal 区域；中心落在其中的文字层行是图的内容（可见文字的证据），不是段落；无 Unicode 映射的字形运行（私用区、U+FFFD）不是文字。
- **上下标**：文字层里字号明显小于所在行主体字号、基线偏上或偏下的字形，是上标或下标；输出 Unicode 上下标或 `$…$`。阈值是相对所在行的比例，不是绝对值。
- 与原生页表格同一套：结构来自版面/引擎，字符来自文字层，文字层不是输出。指导 §6.3 的公式一行据此改写。

### 5.2 哪些页送引擎

- a. 检测器标出的页 ∪ 文字层有数学证据的页（私用区字符；同一行里正文字号与上下标字号的 span 交替出现）；
- b. 文档里只要有一页被标出，整篇原生页都读（一次批量请求；paper_chn02 从 2 页变 7 页；几百页的报告夹一页公式时多几分钟）。

建议 b（少一类漏检、没有阈值），长文档耗时请用户权衡。与 Q56 "不每页过服务 OCR" 的边界：由免费的本地检测器判断哪些文档有非线性内容，只有那些文档读。

### 5.3 区域怎样形成（读数到达之后）

1. 引擎一个公式项里有几组 `$$…$$`，拆成几个区域，框按文字层行的竖向分组切分，分不开时按组数均分；只含编号的一组（`$$ (3) $$`）是前一个公式的编号。
2. 每个区域收进：中心落在框内的原生块；整个落在框内的碎片；与框重叠的检测器公式区域（框取并集）。
3. 编号：文字或引擎 formula_number 项，内容是括号里的编号（现 `NUMBER`），竖向落在区域的行内、在区域右侧；块前带着截下的上标（"-1 （12）"）时上标归区域。一个区域可以有几个编号。
4. 一个 FORMULA 块替换成员（成员 `duplicate_of`；文字层字形拼成它的一条原生 Observation 作证据）。
5. 剩下的原生 TEXT 块与读数文字项按现在的方法配成段落（含 `_continued`），处理行内公式。

`--no-ocr` 或引擎失败：检测器区域内的行仍归一个 FORMULA 块（`paragraphs.py` 不再按字号拆），没有读数，按 IO 约定渲染为文字加 "〔公式未识别〕"，列为失败块。

### 5.4 候选与门：与 `review_table` 同形

候选：引擎读数；不一致时再要编辑（gpt-6-luna，一轮，提示附差异清单）的版本。

`content/select.py` 加 `review_formula`：

| 检查 | 内容 |
|---|---|
| image_evidence | 候选来自页面图像 |
| numeric_consistency | 区域文字层的数字多重集 = 候选的数字多重集（编号除外）。命令名里没有数字，所以不需要"LaTeX 的字符"表；l→1、O→0、1→l 都改变数字多重集，都被抓住 |
| structure_valid | 分隔符与环境配平、非空 |

字母不一致（z→ζ）是 Q56 的"独立读数一致"信号：不拒绝，两份候选都不一致时列待办 `formula_candidate`。`characters()` 只为信号服务，补上 LaTeX 自己定义的算子名（`\min`、`\sin`、`\log`、`\lim` …），与希腊字母同属 LaTeX 的定义表。选择：过门的候选里取字母不一致最少的，同样多取引擎的（确定性）。编辑的非确定性由此只可能变好。

### 5.5 编号

一个编号 `\tag{n}`（现状）。几个编号：按竖向位置对到区域的视觉行，LaTeX 最外层 `\\` 行数与视觉行数相同时 `aligned` 改 `align`、对应行 `\tag{n}`、其余 `\notag`（KaTeX 已验证）；对不上时编号留在公式后各自一行，不猜。引擎自带的 `\tag` 按文字层改。同一规则覆盖扫描页（引擎 formula_number 项）和转写结果是公式的图片（patent01：`\tag` 写进转写块）。"公式块"扩为：kind FORMULA，或整段是 `$$…$$` 的文字块，或 contains 的转写只有一个公式块的图片。

### 5.6 行内公式（段落）

段落的门：数字硬门 + 字母守恒（文字层对正文准确，不为行内结构换掉正文的字）；不过门先要编辑；仍不过保留文字层（正文的退路正确），列待办。`_continued` 去掉 CARRIED=8：相邻读数去掉本段文字层字符后的多余部分，以这一块的字符序列开头或结尾即归入，无长度门槛。它属于段落对齐，以后与"跨栏续接"合并。

## 6. B 线：Word 的矢量图（推迟；与 A 的关系已定）

**是不是同类问题**：原理上同类——要看到"整体"只能看页面图像，散落的形状与文本框就是"文字层的块不是内容的单位"在 Word 上的形态；找整体的规则也相同：页面图像上检测器的 image 区域就是这张图，落在区域里的文字是图的可见文字。不同的是 Word 没有页面图像，先要一个 Word 专有的前提（页面层，Q69：LibreOffice 排版成 PDF），A 线不需要它。所以它是单独的一项工作。**用户决定（2026-09-29）：本轮推迟，先做 A、C。**

**要的输出**（用户，2026-09-29）：不是现在的文字流，也不是 LlamaParse 的 mermaid 代码块（没有必要）。整张图截下来作为一张示意图，加一两句图片说明，和普通示意图一样（IO6 的图画类）。不需要节点与边的结构。难点只在一处：底层是散落的若干小图形，人看是一个整体，要先把它渲染成一个整体再描述。

**做的时候怎么做**（记下备用）：

1. 页面层：LibreOffice 排版成 PDF（`docx_to_pdf` 已有；`-env:UserInstallation` 隔离配置；缺字体会替换、分页会变）。页面渲染只用于检测、看图、裁图，不用于正文与表格的字符（Q69 原结论）。
2. 找整体：对渲染页跑版面检测器，image / chart 区域就是画出来的图——A 线"图片区域里的行归图片"的规则直接套用：区域里的文本框段落是图的可见文字，不再作段落输出（对应关系按文字匹配：渲染页文字层里落在区域内的行 ↔ OOXML 的文本框段落）。检测器把一张图切成几块或漏检时，以形状锚点（`wp:anchor` 的位置与尺寸）在页面坐标里的并集作补充证据。
3. 裁图成 FIGURE 块，走 `describe_figure`（类型 + 一两句）；图画类不转写。
4. 评测：val_word_template01 的图 3–5 各成一张图带说明；unseen_word_spec01 不退步；用户的几篇 Word 收进 `ground_truth_unseen/`，`parserx dev tool-eval run` 跑全部工具并记录在 Word 上跑不起来的原因。
5. 图表（`c:chart`）与 SmartArt 仍按 Q9 遇到时再做；有页面层后至少能裁图描述，不再是失败块。
