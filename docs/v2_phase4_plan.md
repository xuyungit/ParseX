## 0. 目标与退出条件

**目标**：把 Q13 落到产品里（`parserx parse` 默认用混合方案），并补齐典型文档还会碰到的能力缺口。

**退出条件**：

1. `parserx parse` 默认走混合方案：先跑固定流水线，有待核对项就交给 Agent。Agent 不可用、失败或超时时，保留固定流水线的结果，并在文档摘要里说明。
2. **全语料参考运行（L2）**：
   - 扫描类、DOCX、标题三项都不低于 v1；
   - "有信息的图片被丢弃"为 0；
   - 混合方案在信息类指标上不低于固定流水线。
3. 指导 §12、§14、§15 更新，报告写入 `eval_reports/`。

## 1. 各项（按顺序）

| # | 内容 | 做法要点 |
|---|---|---|
| P4-1 | **混合运行时作为产品默认**（Q13） | `runtime.mode: hybrid \| fixed`，默认 hybrid。固定流水线做完后，按分流规则（`review.open > 0` 或状态不是 complete）调用 Agent 处理同一工作区，再导出。Agent 运行时做成可替换的接口：现在是 Codex（gpt-6-sol、medium、看图走 `ask_image`），第三方框架另议。截止时间沿用 Q39。文档摘要记录由哪个运行时产出，以及 Agent 做了什么（修改、关闭的待办、费用）。 |
| P4-2 | **标题的 v2 自有路径** | 编号层级：中文编号体系"一、 >（一）> 1. >（1）"，与点分编号同样作为结构证据。排版证据：D4 的经验是，证据强的直接定，其余作 `title_candidate` 交 Agent。v2 路径在语料上不低于 v1 之前，adapter:v1 保留。 |
| P4-3 | **图片：有信息的图片不丢** | 图片路由对 UNCERTAIN 与有文字的图片生效（阶段一至三只作影子）。统计语料中被丢弃、却有信息的图片，目标为 0。嵌入图片走统一的子文档路径。 |
| P4-4 | **DOCX 的页面**（Q50、Q9） | 经 LibreOffice 排版成 PDF，得到页面图，并把段落与表格对应到页。这样 DOCX 也能用本地读数比对、`ask_image --page` 和 `read --image page`。同时定 OOXML 支持边界（Q9）。 |
| P4-5 | **专项验证** | 低分辨率扫描、密集表格、多栏、旧 OCR 层、矢量文字：各用语料里的一篇核对，哪里处理不好就修哪里（按 §9.5 先定位层）。 |
| P4-6 | **收尾** | 全语料参考运行与报告，更新指导。 |

**不在本阶段做**（原 §12 阶段四所列；没有文档需要时不做）：

- 第二种扫描引擎（VLM 引擎）：paddleocr 目前够用；
- 复核与语义提取的扩展；
- 退役守卫函数：并入阶段五清理。

## 2. 每项完成时

与前几个阶段相同：先写测试；跑 L0 与两个 L1；影响验收文档输出时，空缓存重新冻结并用 `--replay` 验证；更新指导；提交一次（不推送）。
