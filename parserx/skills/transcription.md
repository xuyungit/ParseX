# 忠实转录与纠错

## 目标

让输出里的每一段文字、每一个表格单元格都与原文一致：图上写了什么就是什么。只回答"图上实际写了什么"，不回答"应该写什么"。

## 什么时候需要做

普通区域直接采用扫描页引擎或原生文字层的结果，不默认逐块复核。出现下列具体问题时才处理：

- 表格结构异常：列数前后不一致、数据明显错位、合并单元格丢失；
- 文字提取缺失：页面上看得到的内容在块里找不到；
- 不同来源的证据冲突：同一区域的两份识别结果不一致；
- 工具报告了无法解析、失败或未解决项。

"看起来没问题"不等于正确；数字、单位、日期出错往往是静默的，抽查时优先看这些。

## 取证方法

1. 程序已完成标准处理。待办清单（`read_draft` 的 `issues` 视图）列出需要判断的地方（待识别页、失败块、未采用的复核、续表候选、页面图像与输出不一致之处等），先处理这些。
2. 再做**定向抽查**，不要逐页看原件：优先看含数字、单位、日期的表格和扫描页上的正文；每类抽几处，发现问题再扩大到同类的其他地方。读初稿不花钱，看原件有时间和费用成本：逐页看原件既慢又贵。
3. 需要核对时看原件（`view_source`，方式见任务说明）：块的裁剪图够用就不要看整页。
4. 判断问题属于哪一类：字符（某个字或数字识错）、行列关系（数据归到错误的行列、合并单元格）、还是跨页续接（表格或段落被分页切断）。
5. 按类别处理：
   - 字符错误：用 `edit_draft` 的 `replace_text`（正文）或 `set_cells`（表格）提交修改，`evidence` 填你据以判断的证据；
   - 行列结构错误：用 `view_source` 的 `table` 让视觉模型重读，写清 `structure` 问题与涉及的单元格（漏识的整列：列出该列涉及的所有行，范围内原来没有的内容才能补回），再用 `adopt` 采用；
   - 初稿把块分错了（原件是一张表，初稿却是几段文字；标题和正文连成一块又没有换行可拆）：用 `view_source` 让识别引擎重读那一块区域（`page` 加 `bbox`、`as: text`），读数按块给出；读数的结构对，就用 `adopt`（`page` 加这次的证据）替换区域里的块。程序检查内容守恒：旧块的文字在读数里找得到、原生文字层的数字不变，否则拒绝。区域要框住要替换的块，也不要框进无关的块；区域里的图片不动。采用后发现不对，用 `unadopt` 撤回。两张独立的表被当成续表合在一起时，用 `unjoin` 拆开；
   - 待办清单中的 `text_suspicious`：块里有无法阅读的字符（字体没有对应的 Unicode，如 U+E011、U+FFFD）或全文别处没有的文字系统（可能是把符号认成了字）。对照原件，能确定写法就用 `replace_text` 改（同一块里重复出现的，加 `all: true` 一并替换）；同一个无法阅读的字符出现在很多块里时，核对几处、在最终报告里说明，不必逐块修改；
   - 待办清单中的 `table_arithmetic`：表内的乘积或合计在多数行成立、在这一行不成立，可能是数字识别错了。对照原件核对这一行涉及的格子（`view_source` 加 `rows`，只看这几行、更清楚）：图上与识别结果不同、且改后算术成立就用 `set_cells` 改；图上本来如此（原文自身不一致）就保留，写进最终报告；
   - 待办清单中的 `text_unaccounted`：程序在本地把页面图像读了一遍，这些行（`quotes`，本地读数，可能有个别字认错）在页面上看得到，却不在任何块里。看图确认：是正文、表格内容或标题被漏掉，就补回——在某个格子或段落里漏了一行用 `set_cells` 或 `replace_text` 改那一格或那一段，完全不在任何块里的用 `insert_text`；是图中文字、页面装饰、水印或本地读数把图形认成了字，就不用处理。逐段对照：一行中有一部分已在输出里（例如只有"授权公告日"而没有日期），不等于整行都在，缺的数字、日期、编号要补上。
     - **目标是一张表格时**：这些行落在这张表的区域里，却不在任何格子里。常见的是表头整行丢了（表头是画出来的线条，文字层里没有）、多层表头的一行（如下标）没接上、某格里漏了一行。看这片区域：
       - 缺的只是几格文字：用 `set_cells` 补上；
       - 行列本身不对：用 `view_source` 的 `table` 重读（`structure` 问题写明哪几行缺了什么），或用 `as: text` 加 `page`、`bbox` 重读这片区域，读数对就 `adopt`。`adopt` 被拒、说某几格的文字丢了（cells lost），而图上写的正是重读的样子（文字层的字序或写法与图上不同）：先按图用 `set_cells` 改这几格（证据是看图的结果），再 `adopt`；
       - 本地读数把符号认成了字（例如把"≥8"读成"M8"）：关闭待办。
       - 同一外框拆出的几张表共用一片区域，待办挂在其中第一张上，说明里列出其余几张：这些行可能属于其中任何一张；
   - 待办清单中的 `text_not_seen`：块里的这段文字（`quotes`）在页面图像该处读不到。看图确认：
     - 是扫描软件字样、识别时凭空多出的内容：用 `exclude`（整块）或 `replace_text`（其中一段）去掉；
     - 被页面上别的元素盖住（悬浮的输入框、弹窗、印章、贴在上面的图片），所以看不到：这是原文内容，**保留**，用 `dismiss` 关闭并加 `"occluded": true`，理由写明被什么盖住。摘要会列出这些文字；
     - 图上确实有、只是本地读数没读出来（小字、公式、手写）：保留，用 `dismiss` 关闭。
   - 网页或应用截图里的界面文字（按钮、菜单、输入框里的提示语、工具提示、导航栏）不是文档内容，用 `exclude` 整块去掉，写明理由；页面主体（对话、文章、表单填写的内容）保留。一个块混有几个界面控件时整块排除，不要只删其中一部分。图标被识成的零碎文字同样排除；被误判为页眉页脚的正文用 `include`。
   修改由程序检查后决定是否采用；被拒绝时看结果里的 `rule` 与 `detail`。
   看过原件、确认不需要修改的提示类待办，用 `dismiss` 关闭并写明理由，最终的待核对数只留下真正没解决的。

## 输出要求

- 保留原始数值与写法。原图确实写错的数字也照抄，不依据常识改写。
- 不删除内容：结构调整可以移动单元格内容，不能让任何内容消失。
- 修改必须能指到看原件得到的证据（`evidence`）；只凭"我认为"的改动不是证据。原生文字层里的数字程序不允许改。

## 停止条件

- 同一个问题没有新证据时不再重读原件。
- 看图也无法确定时保留现有结果与冲突，让块保持待定，写明原因，不叠加"再问一次"。
- 预算耗尽（`budget_exhausted`）时停止，文档以 `partial` 导出，缺失项会列在 `missing` 里。

## 公式读数待定（formula_candidate）

含公式的原生页已整页识别；这一段的识别结果（公式为 LaTeX）与文字层相比缺了字符，没有自动采用，识别结果附在待办的引文里。看这一段的图：识别结果对（只是个别字符或公式编号要补），就用 `replace_text` 以它为基础改写这一块，保留图上的每个字符；识别结果不对，用 `dismiss` 关闭并写明理由，文字层保持不变。
