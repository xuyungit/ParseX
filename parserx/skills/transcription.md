# 忠实转录与纠错

## 目标

让输出里的每一段文字、每一个表格单元格都与原文一致：图上写了什么就是什么。只回答"图上实际写了什么"，不回答"应该写什么"。

## 什么时候需要做

普通区域直接采用扫描页引擎或原生文字层的结果，不默认逐块复核。出现下列具体问题时才处理：

- 表格结构异常：列数前后不一致、数据明显错位、合并单元格丢失；
- 文字提取缺失：页面上看得到的内容在块里找不到；
- 不同来源的证据冲突：同一区域的两份识别结果不一致；
- 工具报告了无法解析、失败或未解决项。

"看起来没问题"不等于正确；数字、单位、日期出错往往是静默的，抽查时优先看这些。

## 取证方法

1. 先用 `overview` 看每页状态和未解决项，再用 `read --page N --observations` 看这一页的块和各来源的识别结果。
2. 需要核对时，用 `read --block ID --image crop` 取该块的原图，亲自看图。整页关系不清时用 `--image page` 或扩大 `--context`。
3. 判断问题属于哪一类：字符（某个字或数字识错）、行列关系（数据归到错误的行列、合并单元格）、还是跨页续接（表格或段落被分页切断）。不同类别用不同的处理，不要混在一起。
4. 表格问题用 `review_table`，写清楚是 `char` 还是 `structure`，并给出具体单元格。复核的结果是候选，由程序的接受门决定是否采用；被拒绝时读一下 `gate` 里是哪一项没有通过。

## 输出要求

- 保留原始数值与写法。原图确实写错的数字也照抄，不依据常识改写。
- 不删除内容：结构调整可以移动单元格内容，不能让任何内容消失。
- 修改必须能指到图像证据；只凭"我认为"的改动不是证据。

## 停止条件

- 同一个问题没有新证据时不再复核（工具会以 `invalid_request` 拒绝重复的复核）。
- 看图也无法确定时保留现有结果与冲突，让块保持待定，写明原因，不叠加"再问一次"。
- 预算耗尽（`budget_exhausted`）时停止，文档以 `partial` 导出，缺失项会列在 `missing` 里。
